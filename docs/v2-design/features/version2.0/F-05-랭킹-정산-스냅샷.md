# F-05. 랭킹 · 정산 · 일별 스냅샷

> **문서 버전** v2.0 · **작성일** 2026-08-11 (KST) · **분류** 기능=신규흡수 · 구현=재작성
> **v1.0 대응** 1-13 투자랭킹 (`members.py::investor_rankings`) — 화면에 연결도 안 됐던 API(결함 D-3)

---

## 1. 개요

v1.0 의 투자랭킹은 **전 회원 전기간 단일 랭킹**이었고, 요청이 올 때마다
모든 회원의 모든 포지션을 재계산했다. 참가자가 늘면 무너지는 구조다.

v2.0 은 **일별 스냅샷을 미리 쌓아두고 그걸 읽는** 방식으로 바꾼다.
이 전환 하나가 랭킹·성과지표·회전율·관리점수를 전부 가능하게 만든다.

```
v1.0:  요청 → 전 회원 × 전 포지션 평가 → 정렬 → 응답   (O(회원 × 종목), 30초 캐시로 버팀)
v2.0:  장마감 → 스냅샷 1회 기록 → 요청은 스냅샷만 읽음  (O(참가자), 인덱스 조회)
```

---

## 2. 일별 스냅샷 (`DailySnapshot`)

### 2.1 무엇을 저장하는가

매 영업일 장 마감 후(15:40 KST) 참가자별로 1행씩 기록한다.

| 필드 | 의미 |
|---|---|
| `participation`, `date` | 키 (UNIQUE) |
| `cash` | 현금 |
| `position_value` | 보유 종목 평가액 합 |
| `total_asset` | 순자산 = cash + position_value |
| `nav` | **기준가.** 시작자본을 1000 으로 환산한 지수 |
| `daily_return_pct` | 전일 대비 수익률 |
| `cumulative_return_pct` | 시작 대비 누적 수익률 |
| `position_count` | 보유 종목 수 |
| `invested_ratio_pct` | 편입비 = position_value / total_asset |
| `buy_amount`, `sell_amount` | 당일 매수·매도 금액 (회전율 계산용) |
| `holdings` (JSON) | 종목별 {수량, 평단, 평가액, 비중, 손익} 스냅샷 |
| `sector_weights` (JSON) | 섹터별 비중 |
| `violations` (JSON) | 그날의 한도 초과 상태 |

> **`holdings` 를 JSON 으로 통째 저장하는 이유** — 나중에 "9월 3일에 이 사람이
> 뭘 갖고 있었나"를 복원하려면 포지션 이력이 필요한데, 포지션 테이블은 현재 상태만
> 갖고 있다. 주문 이력에서 역산할 수도 있지만 느리고 실수하기 쉽다.
> 하루 한 번 통째로 찍어두는 게 가장 싸고 정확하다.

### 2.2 기준가(NAV) 방식 ★

타임폴리오 화면의 "Daily NAV" 차트가 이것이다. 순자산 원화 금액이 아니라
**시작자본을 1000 으로 놓은 지수**를 쓴다.

```
NAV = 1000 × (현재 순자산 / 시작 자본)
```

| 왜 | |
|---|---|
| 시작자본이 다른 대회끼리 비교 가능 | 1억 대회와 5천만 대회를 같은 축에 놓을 수 있다 |
| KOSPI·KOSDAQ 지수와 겹쳐 그리기 좋다 | 벤치마크 대비 성과가 한눈에 보인다 |
| 수익률 = (NAV - 1000) / 10 (%) | 계산이 단순하다 |

### 2.3 장중 스냅샷 (Intraday)

타임폴리오는 "Intraday Return (%)" 차트도 보여준다. 장중 수익률 추이다.

- **10분 간격**으로 `IntradaySnapshot` 을 기록한다 (09:00~15:30 → 하루 40행)
- 저장은 `participation`, `at`, `return_pct` **3칸만**. 가볍게 유지한다
- **당일 것만 보관**하고 다음 영업일 시작 시 삭제한다.
  과거 장중 데이터는 `DailySnapshot` 으로 충분하다

## 3. 랭킹

### 3.1 순위 산정

| 순위 종류 | 기준 | 화면 |
|---|---|---|
| **수익률 순위** | 누적 수익률 내림차순 | 대회 메인 |
| **최종 평가 순위** | 수익 점수 백분위 × 0.7 + 관리 점수 백분위 × 0.3 | 대회 종료 후 |

> *"[순위]: 액티브 포트의 수익률의 순위. 운영 능력 평가와는 무관"* (타임폴리오 안내문)
>
> 즉 **진행 중에 보이는 순위 = 단순 수익률**이고, **최종 수상 = 관리 점수 반영**이다.
> 우리도 같게 한다. 진행 중에 복잡한 점수를 보여주면 참가자가 전략을 세울 수 없다.

### 3.2 랭킹 테이블 컬럼

타임폴리오 캡처 기준으로 구성한다.

| 그룹 | 컬럼 |
|---|---|
| 순위 | 현재 순위 · **등락**(전일 대비 `3↑` `2↓` `-`) |
| 별칭 | 별칭 |
| 기준가 | 현재 NAV · 등락(당일 %) |
| 포트폴리오 | **편입비** · **종목수** · 상세 보기 버튼 |

- `is_ranked = False`(실격·포기)인 참가자는 **목록에 표시하되 순위 칸을 `-`** 로 둔다.
  아예 숨기면 "내가 왜 없지?"라는 문의가 온다.
- 내 행은 **하이라이트**하고, 목록이 길어도 내 위치로 스크롤하는 버튼을 둔다.

### 3.3 참가자 포트폴리오 공개 ★ (v2.0 차별점)

> 벤치마크 결함 ③: **50등 이후 참가자는 포트폴리오 조회가 불가능하다.**
> 같은 동아리인데 서로 배울 수가 없다.

**v2.0 은 전 참가자의 포트폴리오를 공개한다.**

상세 모달 구성 (타임폴리오와 동일 + 확장):

```
[별칭]
├── Intraday Return (%)  차트 — Portfolio vs KOSPI vs KOSDAQ
├── Daily NAV            차트 — Portfolio vs KOSPI vs KOSDAQ
├── 보유 종목 (전체)      ← 타임폴리오는 Top 10 만. 우리는 전체 공개
│     코드 · 종목명 · 현재가 · 당일% · 잔고 · 비중% · 평가액 · 평단 · 손익률 · 손익
├── 수익 종목 (전체)      ← 타임폴리오는 Top 10 만
│     종목코드 · 종목명 · 손익 · 수익/총수익(%)
└── 거래 이력            ← 신규. 언제 사고팔았는지까지 공개
```

**공개 범위를 대회 설정으로 조절 가능하게 한다** (`Contest.portfolio_visibility`).
외부 공개 대회라면 `TOP_N` 으로 제한할 수도 있어야 한다.

| 값 | 의미 |
|---|---|
| `ALL` | 전 참가자 전체 공개 (동아리 기본값) |
| `TOP_N` | 상위 N명만 |
| `SELF_ONLY` | 본인 것만 |

### 3.4 Top Pick — 종목 × 참가자 매트릭스

타임폴리오의 인상적인 화면이다. **수익률 상위 참가자들이 무엇을 담고 있는지**를
히트맵 매트릭스로 보여준다.

```
          uzzan  드래곤  안온  wioefls  귤22  ...
삼성전자    4.0          5.9          34.3
SK하이닉스  3.0          7.0          22.7
NAVER                          5.9   
에코프로   10.8         4.8
```

- 행 = 종목(수익률 상위 참가자들의 주요 종목 30개), 열 = 참가자
- 셀 = 그 참가자의 해당 종목 비중 %. 값이 클수록 진한 색
- **전일 종목 / 당일 종목** 토글
- 이 화면 하나로 "지금 잘하는 사람들이 뭘 사고 있나"가 보인다 — 학습 효과가 크다

### 3.5 참여 포트폴리오 분석 (산점도)

x축 = 관리 점수, y축 = 수익 점수인 산점도. 참가자 전체의 분포를 한눈에 본다.
"수익은 높은데 관리가 나쁜 사람" / "둘 다 좋은 사람"이 시각적으로 구분된다.

## 4. 정산

### 4.1 일별 정산 (매 영업일)

```
15:30  장 마감
15:40  ① 종가 확정 대기 → 최종가 수집
       ② 참가자별 포지션 평가 → DailySnapshot 기록
       ③ NAV · 수익률 계산
       ④ 순위 산정 → ContestRanking 갱신
       ⑤ 한도 위반 상태 기록
16:00  ⑥ 주간 회전율 갱신 (주중 누적치)
```

### 4.2 주간 정산 (매주 월요일 06:00)

```
① 지난 주 회전율 확정
② 위반 여부 판정 → WeeklyTurnover 기록
③ 누적 위반 4회 도달 시 DISQUALIFIED 처리 + 알림
```

### 4.3 최종 정산 (대회 종료일 다음 영업일 06:00)

```
① 대회 상태 ONGOING → SETTLING
② 최종 스냅샷 확정
③ 관리 점수 계산 (수익 분산 · 포트 분산)
④ 백분위 변환 → 최종 점수 → 등급 부여
⑤ ContestResult 확정 기록
⑥ 모든 대회 계좌 is_frozen = True
⑦ 대회 상태 SETTLING → CLOSED
```

**정산은 멱등해야 한다.** 같은 날짜로 두 번 돌아도 결과가 같아야 한다.
`DailySnapshot` 은 `UNIQUE(participation, date)` 로 두고 upsert 한다.

> v1.0 스케줄러는 `crypto_rank` 를 `TRUNCATE` 후 재적재했다(결함).
> 동기화 중에 조회하면 빈 테이블이 보이는 창이 생긴다. v2.0 은 **전부 upsert** 로 간다.

### 4.4 벤치마크 지수 스냅샷

NAV 차트에 KOSPI·KOSDAQ 을 겹쳐 그리려면 지수도 같이 저장해야 한다.

`MarketIndexSnapshot(date, index_code, close, nav)` — 대회 시작일을 1000 으로 환산한 NAV 를 함께 기록.

## 5. 성과 지표 (v2.0 1차 범위)

일별 스냅샷이 쌓이면 다음 지표를 계산할 수 있다.

| 지표 | 산식 | 1차 |
|---|---|---|
| 누적 수익률 | (최종 NAV - 1000) / 10 | ✅ |
| 일별 수익률 | 전일 대비 | ✅ |
| **MDD** (최대 낙폭) | max(고점 대비 하락률) | ✅ |
| 변동성 | 일별 수익률 표준편차 × √영업일수 | ✅ |
| **샤프 지수** | (연환산 수익률 - 무위험수익률) / 변동성 | ✅ (무위험수익률 = 3% 고정) |
| 승률 | 수익 종료 거래 / 전체 종료 거래 | ✅ |
| 벤치마크 대비 초과수익 | 포트 수익률 - KOSPI 수익률 | ✅ |
| 베타 · 정보비율 | | v2.1 |

> 대회 기간이 1달(약 20영업일)이라 샤프·변동성의 통계적 신뢰도는 낮다.
> **화면에 "표본 기간이 짧아 참고용"이라는 주석을 붙인다.**

## 7. 성능 설계

v1.0 이 랭킹 API 에서 취한 판단은 **옳았고, v2.0 도 승계한다.**

> v1.0 주석: *랭킹 패널은 즉시 떠야 하므로 주식은 외부 시세를 기다리지 않고
> `cached_price()`(마지막 조회값)만 쓰고, 없으면 매입단가로 평가한다.*

v2.0 에서는:

- **랭킹 조회는 절대 외부 API 를 호출하지 않는다.** 스냅샷과 시세 캐시만 읽는다
- 장중 실시간 순위는 **10분 간격 `IntradaySnapshot`** 기준. 초 단위로 순위가 흔들리면
  오히려 산만하고, 참가자 수 × 종목 수만큼 평가 연산이 든다
- 랭킹 목록은 **`ContestRanking` 을 그대로 읽는다.** 정렬·계산을 요청 시점에 하지 않는다
