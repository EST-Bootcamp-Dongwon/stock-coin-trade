## 2. 두 개의 화면

### 2.1 전체 자산 요약 (`/portfolio/`)

**모든 계좌를 한눈에.** v1.0 의 통합 뷰 감각을 유지하는 화면이다.

```
┌─ 총 자산 (전 계좌 합) ─────────────────────┐
│  현금 · 평가액 · 총 손익 · 총 수익률          │
└────────────────────────────────────────┘
┌─ 계좌 카드 4장 ────────────────────────────┐
│ [주식 연습]  [코인 연습]  [대체자산 연습]  [대회: RFM 1회] │
│  각 카드: 순자산 · 수익률 · 보유 종목 수 · 미니 스파크라인   │
└────────────────────────────────────────┘
┌─ 자산 배분 도넛 ───────────────────────────┐
│  계좌별 비중 (Highcharts)                    │
└────────────────────────────────────────┘
```

> **주의** — 여기서 "총 수익률"을 계산해 보여주되, **이건 순위와 무관하다**는 점을
> 명시한다. 대회 순위는 대회 계좌만 본다.

### 2.2 계좌 상세 (`/portfolio/<account_id>/`)

한 계좌의 보유 내역. v1.0 의 테이블을 그대로 옮긴다.

| 요소 | 처리 |
|---|---|
| 보유 종목 테이블 | 종목 · 수량 · 평단 · 현재가 · 평가액 · 비중 · 손익 · 손익률 |
| 코인 실시간 갱신 | **유지** — 업비트 WebSocket 으로 평가금액·수익률 실시간 |
| 섹터별 평가 비중 집계 | 유지 |
| Highcharts 도넛 2종 (종목 배분 / 섹터 배분) | 유지 |
| 종목별 물타기 버튼 | 유지 (→ [F-11](F-11-물타기-시뮬레이터.md)) |
| **자산 추이 차트** | **신규** — `DailySnapshot` 기반 일별 순자산 추이 |

## 3. 계좌 스냅샷 API (통합)

```
GET /api/accounts/<id>/snapshot
```

한 번의 호출로 화면 전체를 그릴 수 있는 데이터를 준다.

```jsonc
{
  "account": { "id": 1, "mode": "PRACTICE_STOCK", "cash": 42350000 },
  "summary": {
    "total_asset": 103820000, "position_value": 61470000,
    "total_pnl": 3820000, "total_pnl_pct": 3.82
  },
  "positions": [ { "symbol": "005930", "name": "삼성전자", "qty": 100,
                   "avg_price": 71200, "current_price": 74300,
                   "value": 7430000, "weight_pct": 7.16,
                   "pnl": 310000, "pnl_pct": 4.35, "sector": "전기전자" } ],
  "sector_weights": [ { "sector": "전기전자", "weight_pct": 32.1 } ],
  "as_of": "2026-08-11T14:23:11+09:00"
}
```

**HTMX 부분 갱신 단위와 일치시킨다.** 이 응답 하나로 요약 카드·테이블·도넛이
전부 갱신되도록 설계한다(→ [ui/01-HTMX-부분갱신-규약](../../ui/version2.0/01-HTMX-부분갱신-규약.md)).

## 4. 포트폴리오 분석 (규칙 기반)

v1.0 의 `GET /api/member/portfolio-analysis` 를 승계한다.

### 4.1 v1.0 동작

현금·주식·코인·대체자산 4분류 비중을 계산하고 **하드코딩된 임계값**으로 조언을 만든다.
**AI 가 아니다.**

| 임계값 | 조언 |
|---|---|
| 한 자산군 ≥ 65% | 집중 경고 |
| 코인 ≥ 30% | 변동성 경고 |
| 대체자산 ≥ 35% | 집중 경고 |
| 현금 ≥ 50% | 유휴 자금 안내 |

응답에 `"모의투자 교육용 분석이며 개인별 투자 권유가 아닙니다."` 고지 포함.

### 4.2 v2.0 처리

**규칙 기반을 유지한다.** LLM 으로 승격하지 않는다.

이유:
- 즉시 응답하고 비용이 0이다
- 판정 근거가 명확해 학습자가 "왜 이런 조언이 나왔나"를 이해할 수 있다
- LLM 분석은 이미 [F-14 AI 분석](F-14-AI분석.md)이 담당한다. 역할이 겹친다

**개선점**: 임계값을 하드코딩 → 설정값으로 빼고, 계좌 분리 구조에 맞게 재작성한다.
전 계좌 합산 기준으로 판정하되 "어느 계좌 때문인지"를 함께 알려준다.

### 4.3 대회 계좌에서는 다르게

대회 계좌는 규칙 기반 조언 대신 **[F-04 규칙 엔진](F-04-대회-규칙엔진.md)의 한도 현황**을 보여준다.
"코인 비중이 높습니다" 같은 조언은 주식만 담는 대회에서 의미가 없다.
