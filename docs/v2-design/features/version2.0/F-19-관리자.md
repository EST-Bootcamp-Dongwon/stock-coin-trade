## 1. v1.0 의 상태

| 항목 | 상태 |
|---|---|
| 화면 | **없음** |
| API | `GET /api/admin/me` **1개** |

| 호출하는 프론트 코드 | **0건** (`grep -rn "api/admin" frontend/` → 0) |

**살릴 코드가 사실상 없다.** (결함 D-1)

## 2. Django Admin 을 쓰는 이유 ★

v2.0 은 대회 도메인이 들어오면서 **운영 화면이 프로젝트의 절반**을 차지한다.
대회 생성·참가자 관리·주문 조회·수동 정산·부정 점검을 전부 직접 만들면
그것만으로 몇 주가 든다.

**Django Admin 은 모델 정의만으로 이 화면들을 만들어 준다.**
이것이 Django 를 선택한 가장 큰 실익이다.

> **Django 관점** — FastAPI 에는 이에 대응하는 기본 제공 관리자가 없다.
> `sqladmin` 같은 서드파티를 붙이거나 직접 만들어야 한다.
> Django 는 `admin.site.register(Contest)` 한 줄로 목록·검색·필터·상세·수정 화면이 나온다.
> 커스터마이징도 `ModelAdmin` 클래스에 속성을 얹는 방식이라 학습 곡선이 완만하다.

## 3. 관리 대상

### 3.1 대회 운영 (최우선) ★

| 화면 | 기능 |
|---|---|
| **대회 목록·생성·수정** | 기간 · 시작자본 · 수수료율 · `rule_set` JSON · 공개 범위 |
| **참가자 관리** | 승인/거절 · 실격 처리 · 실격 해제 · 별칭 수정 |
| **주문 조회** | 전 참가자 주문. 종목·기간·상태·경로 필터 |
| **수동 정산** | 특정 날짜 정산 재실행 (배치 실패 복구용) |
| **규칙 위반 현황** | 한도 초과 지속 참가자 목록 → "적극적 해소 노력" 판단 근거 |
| **부정거래 점검** | 이상 패턴 목록 (아래 3.4) |

### 3.2 데이터 운영

| 화면 | 기능 |
|---|---|
| 종목 마스터 | pykrx 수집 결과 확인·수동 보정 |
| 영업일 캘린더 | 임시 휴장일 등록 |
| **배치 실행 이력** | `DataSyncLog` — 실패 잡 상단 강조 (→ [F-20](F-20-스케줄러.md) 5장) |
| pg_cron 잡 상태 | `cron.job_run_details` 읽기 전용 |
| 캐시 상태 | 각 캐시 테이블의 최신 갱신 시각 |

### 3.3 콘텐츠 운영

| 화면 | 기능 |
|---|---|
| 학습 레슨 | 콘텐츠 수정 (→ [F-17](F-17-학습콘텐츠.md) 2.2) |
| 가이드 | `last_verified_at` 갱신 |
| **지식 문서 승인** | 사용자 추가 문서 검토·승인 (→ [F-15](F-15-지식검색-RAG.md) 5장) |
| 대체자산 상품 | 카탈로그 추가·수정 (→ [F-08](F-08-대체자산-연습모드.md) 3장) |

### 3.4 부정거래 점검 (신규)

대회에서는 순위가 걸려 있으므로 이상 패턴을 볼 수 있어야 한다.

| 점검 | 의미 |
|---|---|
| **자전거래 의심** | 같은 종목을 짧은 간격으로 매수·매도 반복 (회전율만 채우는 행위) |
| 비정상 체결 | 호가 대비 지나치게 유리한 체결 (엔진 버그 가능성) |
| 급증 주문 | 짧은 시간에 주문 수 급증 (봇 오작동) |
| API 남용 | rate limit 근접 키 |

**자동 제재는 하지 않는다.** 목록만 제공하고 판단은 운영자가 한다.
([F-04](F-04-대회-규칙엔진.md) 3.4 와 같은 원칙)

## 4. 권한

| 역할 | Django 판정 | 범위 |
|---|---|---|
| 슈퍼유저 | `is_superuser` | 전체 |
| 대회 운영자 | `Group("contest_admin")` | 대회·참가자·주문 조회 |
| 콘텐츠 운영자 | `Group("content_admin")` | 레슨·가이드·지식 문서 |

**이메일 하드코딩은 폐기한다.**

## 5. Admin 커스터마이징 지점

기본 Admin 만으로 부족한 부분이다.

| 항목 | 처리 |
|---|---|
| **대회 대시보드** | Admin 홈에 커스텀 위젯 — 진행 중 대회 · 최근 배치 실패 · 승인 대기 건수 |
| **정산 재실행 버튼** | `ModelAdmin.actions` 로 "선택한 날짜 정산 재실행" |
| `rule_set` JSON 편집 | 원시 JSON 대신 **폼 필드로 펼쳐 보여주기** (실수 방지) |
| 읽기 전용 보호 | 정산 완료(`CLOSED`) 대회의 주문·스냅샷은 수정 불가 |

## 6. 감사 로그 ★

운영자가 대회 데이터를 손대는 일은 **반드시 기록**되어야 한다.
순위에 영향을 주는 조작이 흔적 없이 일어나면 안 된다.

```
AdminAuditLog(actor, action, target_model, target_id, before(JSON), after(JSON), reason, created_at)
```

- 참가자 실격·해제, 주문 수정·삭제, 정산 재실행, `rule_set` 변경은 **사유 입력 필수**
- 대회 상세 화면에 "운영자 조치 이력"을 참가자에게도 공개할지는 대회 설정으로
