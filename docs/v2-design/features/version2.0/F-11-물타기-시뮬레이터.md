> **문서 버전** v2.0 · **분류** 기능=개선 · 구현=수정포팅
> **v1.0 대응** 1-6 물타기 (`avg_down.js` 106줄) + **우리 구현 `899ac83`** (`stock.js` +342줄)

## 1. 두 구현의 통합

인벤토리에서 확정한 대로 **v1.0 계산 로직을 기준으로 삼고, 우리 구현의 고급 기능
①~⑤ 를 전부 얹는다.** 진입점은 두 개를 모두 제공한다.

| 진입점 | 성격 |
|---|---|
| **독립 계산기** `/tools/avg-down/` | 보유 없이도 숫자만 넣어 계산. v1.0 방식 |
| **포지션 연동 모달** | 주문 패널 · 보유 포지션 테이블의 종목별 버튼에서 열림. 우리 구현 방식 |

## 2. 계산 기능

### 2.1 정방향 (v1.0 승계)

입력: 보유 수량 · 보유 평균가 · 추가 매수가 · (수량 또는 금액)

출력:
- 추가 매수 금액 · 추가 매수 수량
- 총 보유 수량 · 총 매수 금액
- **신규 평균 매수가** · 평균가 변동률

**수량/금액 입력 모드 전환**(라디오)도 그대로 유지한다.

### 2.2 목표 평균가 역산 (v1.0 승계)

```
requiredQty = holdQty × (holdAvg − targetAvg) / (targetAvg − buyPrice)
```

도달 불가능한 목표(목표가가 보유 평단과 추가 매수가 사이가 아닌 경우)를 감지해 안내한다.

### 2.3 고급 기능 ①~⑤ (우리 구현에서 이관)

| # | 기능 | 설명 |
|---|---|---|
| ① | **목표 평단 역산** | v1.0 에도 있으나, 포지션 연동 시 **타이핑이 불필요**하다 |
| ② | **본전까지 필요 상승률** | 물타기 후 평단 기준으로 현재가가 몇 % 올라야 손익분기인지. **v1.0 에 없던 기능** |
| ③ | **슬라이더 + 비율 버튼** | 수량 슬라이더(0~최대) + 현금 10%/25%/50%/전액. **보유 현금으로 살 수 있는 최대 수량까지만** 동작하도록 상한 |
| ④ | **주문 실행** | 시뮬레이션한 조건 그대로 매수 주문 실행. 계산에서 주문까지 끊김 없이 |
| ⑤ | **포지션별 진입점** | 종목·보유수량·평단·현재가·보유현금이 **자동으로 채워짐** |

### 2.4 우리 구현에만 있던 세부 동작 (전부 유지)

- 실시간 시세와 매수 단가 **자동 동기화** (사용자가 단가를 직접 수정하면 동기화 중단)
- 평단보다 **비싸게** 추가 매수하면 평단이 오른다는 점을 **배지로 경고**
- 결과 표시: 물타기 후 평단 · 평단 변동 · 총 보유 수량 · 총 매수 원금 ·
  **현재가 기준 수익률** · 본전까지 필요 상승률 · **잔여 현금**

## 3. v2.0 신규 확장

### 3.1 전 자산군 지원 ★

v1.0 도 우리 구현도 **주식 전용**이었다. v2.0 은 코인·대체자산에도 적용한다.

| 자산군 | 차이 |
|---|---|
| 주식 | 수량 정수. 평단 `int` 절사 |
| **코인** | **수량 소수점 8자리.** 원화 금액 입력 모드가 기본 |
| **대체자산** | **증거금 기반** — 명목금액이 아니라 납부 증거금으로 계산해야 한다 |

### 3.2 수수료·세금 반영 ★

v1.0·우리 구현 모두 수수료가 없어 계산이 단순했다.
v2.0 은 수수료가 생기므로 **"실제로 들어가는 현금"이 체결금액보다 크다.**

```
필요 현금 = 추가매수금액 + 수수료
잔여 현금 = 보유현금 − 필요 현금
```

**슬라이더 상한(③)도 수수료를 포함해 계산**해야 한다.
안 그러면 "전액" 버튼을 눌렀을 때 잔고 부족으로 주문이 거부된다.

### 3.3 대회 모드에서의 한도 검증

대회 계좌에서 물타기 모달을 열면 **편입 한도를 함께 표시**한다.

```
물타기 후 삼성전자 비중: 38.5% → 42.1%   ⚠️ 한도 40% 초과
최대 추가 매수 가능액: 15,230,000원
```

[F-04](F-04-대회-규칙엔진.md) 4.2 의 `max_additional_krw` 를 그대로 쓴다.
**주문을 눌러야 거부되는 게 아니라 미리 보인다.**

### 3.4 시뮬레이션 이력 저장 (선택 기능)

물타기 시뮬레이션 결과를 저장해두면 "계획 대비 실제"를 회고할 수 있다.

- `AvgDownSimulation(account, symbol, params(JSON), result(JSON), executed_order, created_at)`
- 주문으로 이어졌으면 `executed_order` 로 연결
- **1차에는 저장만 하고 회고 화면은 v2.1** 로 미룬다

## 4. 계산 위치

| 항목 | 위치 |
|---|---|
| 계산 | **클라이언트 (Alpine.js)** — 슬라이더를 움직일 때마다 즉시 반응해야 한다 |
| 한도 검증 | 서버 (모달 열 때 1회 조회해 상한값을 받아둠) |
| 주문 실행 | **서버** (권위) |

> v1.0 도 계산을 클라이언트에서 했다. 옳은 판단이라 유지한다.
> 다만 **주문은 반드시 서버가 다시 검증**한다. 클라이언트 계산을 신뢰하지 않는다.
