## 1. 왜 모드를 나누는가

v1.0 은 **모드 개념이 없다.** 회원 한 명이 현금 1억(`member.asset`) 한 칸을 갖고
주식·코인·대체자산을 전부 그 한 칸으로 사고판다. 그래서 "누가 잘했는가"를 물으면
답이 하나뿐이고, 규칙을 걸 자리가 없다.

v2.0 은 **대회(Contest)를 전면 도입**한다. 그런데 대회 규칙(타임폴리오 룰)을 전 기능에
일괄 적용하면 v1.0 의 자유로운 실습 기능이 전부 죽는다. 예를 들어

- 코인은 24시간 거래되는데 대회는 장 운영시간에만 거래 가능해야 한다
- 대체자산은 시세가 결정론적 수식이라 대회에 넣으면 순위 조작이 가능하다
- 물타기·Pine 같은 실습 기능은 규칙 없이 자유롭게 눌러봐야 학습이 된다

그래서 **모드를 4개로 분리**하고, 규칙 엔진은 대회 모드에만 건다.

## 2. 모드 4종

| 모드 | 코드 | 자산군 | 규칙 | 계좌 | 거래 가능 시간 |
|---|---|---|---|---|---|
| **대회** | `CONTEST` | 주식만 | 타임폴리오 룰 전면 적용 | 대회별 참가 계좌 | **장 운영시간만** (09:00~15:30 KST, 영업일) |
| **주식 연습** | `PRACTICE_STOCK` | 주식 | 없음 (수수료만) | 개인 연습 계좌 1개 | 상시 (장외에는 최종가로 체결) |
| **코인 연습** | `PRACTICE_CRYPTO` | 코인 | 없음 (수수료만) | 개인 연습 계좌 1개 | 24시간 |
| **대체자산 연습** | `PRACTICE_ALT` | 선물·옵션·금·은·부동산 11종 | 없음 (증거금만) | 개인 연습 계좌 1개 | 상시 |

### 2.1 핵심 원칙 — 계좌는 모드마다 독립이다

```
Member (회원 1명)
 ├── Account(PRACTICE_STOCK)   현금 1억 · 주식 포지션
 ├── Account(PRACTICE_CRYPTO)  현금 1억 · 코인 포지션
 ├── Account(PRACTICE_ALT)     현금 1억 · 대체자산 포지션
 ├── Account(CONTEST, contest=RFM 1회)   시작자본 = 대회 설정값
 └── Account(CONTEST, contest=RFM 2회)   시작자본 = 대회 설정값
```

- v1.0 의 `member.asset` **한 칸을 여러 자산군이 공유하던 구조를 폐기**한다.
  이것이 v1.0 결함 D-5(계좌 초기화가 코인을 안 지움)의 근본 원인이었다.
- 연습 계좌는 **회원 가입 시 3개가 자동 생성**된다. 각각 초기 자본 1억.
- 대회 계좌는 **참가 신청 시점에 생성**되고, 대회가 끝나면 읽기 전용으로 동결된다.
- 계좌 초기화는 **해당 모드 계좌만** 초기화한다. 연습 계좌는 언제든 초기화 가능,
  **대회 계좌는 초기화 불가**(당연히).

> **Django 관점** — FastAPI + SQLAlchemy 에서는 `Member` 에 `asset` 컬럼을 두고
> 서비스 계층에서 직접 만졌다. Django 에서는 `Account` 를 별도 모델로 두고
> `member.accounts.get(mode="CONTEST", contest=c)` 처럼 **역참조 매니저**로 꺼낸다.
> `related_name` 을 `accounts` 로 지정해두면 이 접근이 가능해진다.

### 2.2 모드가 자산군을 하나만 갖는 이유

v1.0 은 한 화면(`/trade/hold.html`)에 주식·코인·대체자산 3개 테이블을 함께 보여줬다.
편리하지만 **수익률을 정의할 수 없다.** 코인으로 번 돈과 주식으로 잃은 돈이 섞이면
"주식 실력"을 측정할 수 없다.

v2.0 은 계좌를 자산군별로 쪼개서 **각 모드가 자기 수익률을 갖게** 한다.
통합 보기가 필요하면 "전체 자산 요약" 화면에서 4개 계좌를 나란히 보여준다
(→ [F-09 보유자산·포트폴리오](F-09-보유자산-포트폴리오.md)).

## 3. 대회 모드 = 타임폴리오 룰

벤치마크는 `contest.timefolio.net` (RFM — Road to Fund Manager 투자 대회).
사용자가 제공한 대회 규칙 전문과 화면 캡처 25장을 기준으로 삼는다.

### 3.1 v2.0 1차에 넣는 것 (사용자 확정)

| # | 규칙 | 문서 |
|---|---|---|
| 1 | 종목 편입한도 15% + 대형주 예외(삼성전자 40% · SK하이닉스 30%) | [F-04](F-04-대회-규칙엔진.md) |
| 2 | 주문 비중(%) 입력 방식 — 수량이 아니라 순자산 대비 % | [F-03](F-03-주문-체결엔진.md) |
| 3 | 주간 회전율 5% + 위반 카운터(최대 3회 허용) | [F-04](F-04-대회-규칙엔진.md) |
| 4 | 관리 점수(수익 분산 · 포트 분산) 상대평가 | [F-05](F-05-랭킹-정산-스냅샷.md) |
| 5 | 거래 불가 종목 자동 차단 (5일 거래대금 30억 · 시총 1000억 · 관리종목 등) | [F-04](F-04-대회-규칙엔진.md) |
| 6 | 섹터 비중 한도 (시장 비중 2배, 5% 이하 섹터는 10%까지) | [F-04](F-04-대회-규칙엔진.md) |
| 7 | 시총 1조 미만 합산 비중 30% 이하 | [F-04](F-04-대회-규칙엔진.md) |
| 8 | 거래 비용 — 수수료 10bp · 매도세 20bp | [F-03](F-03-주문-체결엔진.md) |
| 9 | KIS 실호가 기반 체결 (상대호가·자기호가·지정가·STOP) | [F-03](F-03-주문-체결엔진.md) |
| 10 | 참가자 포트폴리오 공개 · Top Pick 매트릭스 | [F-05](F-05-랭킹-정산-스냅샷.md) |

### 3.2 v2.1 이후로 미루는 것 (명시적 유예)

| 규칙 | 왜 미루는가 |
|---|---|
| **시간 분할 주문** | 주문 조각(slice) 스케줄링·미체결 취소·재제출이 필요하다. 비동기 워커 아키텍처가 선행되어야 하는데 1차는 "즉시 체결 + 예약주문"으로 확정했다 |
| **과주문 후 대기 (n분 체결 정지)** | 시장 충격 모델링. 체결 엔진이 안정화된 뒤에 얹는 게 맞다 |
| **기업 이벤트 처리** | 유·무상증자, 현금·주식 배당, 액면변경, 분할·합병. 각각 권리락일·상장일·매매제한 기간이 다르고 데이터 소스도 따로 필요하다. 1차는 **대회 기간(1달) 중 발생하면 운영자가 Django Admin 에서 수동 조정**한다 |
| **주문 정정** | 1차는 **취소 후 재주문**만 제공. 정정은 미체결 잔량 관리가 얽힌다 |
| **동시호가(단일가) 세션** | 08:30~09:00 / 15:20~15:30 의 단일가 매매. 1차는 이 시간대 주문을 **접수만 하고 정규장 시작 시 처리** |
| **공매도·숏 포지션** | 타임폴리오 규칙에도 없다. 증거금·마진콜·강제청산이 함께 와야 의미가 있어 1차 범위를 크게 늘린다 |
| **Pine 전략 자동 실행** | 1차는 수동 실행만. 자동매매가 필요하면 Open API(자기 봇) 경로로 유도 |

> **유예 원칙** — 미루는 규칙은 **화면에 "v2.1 예정"으로 표시**하거나 아예 노출하지 않는다.
> 버튼만 있고 동작하지 않는 상태(= v1.0 의 결함 D-1·D-3 패턴)를 반복하지 않는다.

## 4. 연습 모드 = v1.0 기능 보존

강사님의 "이 기능들은 웬만하면 다 들어가야 한다"는 요구를 **연습 모드가 받는다.**
v1.0 의 20종 기능은 대회 모드가 아니라 연습 모드에서 살아남는다.

| v1.0 기능 | v2.0 위치 |
|---|---|
| 주식 거래(호가창·관심종목·포트폴리오 도넛·계좌초기화) | `PRACTICE_STOCK` |
| 코인 거래(업비트 WebSocket·4대 거래소 비교) | `PRACTICE_CRYPTO` |
| 대체투자 11종(증거금·부동산 지도) | `PRACTICE_ALT` |
| 물타기 시뮬레이터 | 3개 연습 모드 전부 + 대회 모드 |
| Pine 전략거래 | `PRACTICE_STOCK` (대회는 수동 주문만) |
| Open API | 연습·대회 양쪽 (대회는 계좌 지정 필수) |
| AI 분석 · 지식검색 RAG · KRX 뉴스 | 전 모드 공통 (우측 패널) |
| 학습 콘텐츠 14레슨 · 가이드 3종 | 모드 무관 (독립 메뉴) |
| 웹 데이터 수집기(구 AI Sheet) | 모드 무관 (도구 메뉴) |

**연습 모드에도 수수료·세금은 적용한다.** 실제 감각을 익히는 것이 목적이고,
수수료가 없으면 "하루 100번 회전매매해도 손실 0"이라는 비현실적 학습이 된다.
다만 요율은 대회(10bp/20bp)와 달리 **실제 국내 기준**을 쓴다 (→ [F-03](F-03-주문-체결엔진.md) 5장).

## 5. v2.0 1차 릴리스 범위 경계

### 5.1 1차에 반드시 들어가는 것

```
[기반]      계정·인증 · 계좌 4종 · Django Admin · pg_cron
[대회]      대회 CRUD · 참가 · 규칙 엔진 · 체결 엔진 · 랭킹 · 일별 스냅샷
[연습]      주식 · 코인 · 대체자산 3종 + 물타기 + Pine(수동)
[데이터]    KIS 실호가 · pykrx 일배치 · 업비트 · 네이버/yfinance 폴백 · KRX 뉴스
[부가]      AI 분석 · 지식검색(pgvector) · 학습 콘텐츠 · Open API · 웹 데이터 수집기
```

### 5.2 1차에서 빼는 것

| 항목 | 처리 |
|---|---|
| 시간분할 주문 · 과주문 대기 · 주문 정정 · 기업 이벤트 · 동시호가 | v2.1 (→ 3.2절) |
| 공매도 · Pine 자동실행 | v2.1 이후 |
| Pine 백테스트 | v2.1 — 과거 봉 저장이 선행되어야 한다 |
| 코인·대체자산 **대회** | v2.2 — `Contest.asset_class` 필드는 1차에 미리 만들어두고 값은 `STOCK` 만 허용 |
| 소셜 로그인 · 이메일 인증 | v2.1 (1차는 아이디/비밀번호) |
| 모바일 전용 UI | 1차는 반응형 대응까지만 (전용 앱 없음) |

### 5.3 확장 여지를 미리 남기는 지점

1차에 만들지는 않지만 **모델·설정에 자리만 만들어 두는 것**들이다.
나중에 마이그레이션을 다시 하지 않기 위해서다.

| 자리 | 이유 |
|---|---|
| `Contest.asset_class` (`STOCK` / `CRYPTO` / `ALT`) | 사용자 요구 — "지금은 주식이지만 나중에 코인 대회도" |
| `Contest.rule_set` (JSON) | 대회마다 한도·요율을 바꿀 수 있게. 하드코딩하면 2회 대회에서 막힌다 |
| `Order.execution_mode` (`IMMEDIATE` / `SLICED`) | 시간분할을 v2.1 에 얹을 때 컬럼 추가 없이 |
| `Order.source` (`WEB`/`PINE`/`OPENAPI`/`ADMIN`/`DEMO_SEED`) | v1.0 에서 이미 검증된 설계. 그대로 승계 |
| `Account.is_frozen` | 대회 종료 후 동결 |
