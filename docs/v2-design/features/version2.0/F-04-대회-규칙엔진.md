# F-04. 대회 규칙 엔진

> **문서 버전** v2.0 · **작성일** 2026-08-11 (KST) · **분류** 기능=신규 · 구현=신규작성
> **적용 범위** 대회 모드 전용. 연습 모드에는 걸지 않는다
> **데이터 소스** pykrx 일배치 (사용자 확정)

---

## 1. 개요

주문이 접수되기 전에 통과해야 하는 검증 규칙 모음이다.
타임폴리오 규칙을 **"주문 시 자동 체크"** 되는 것과 **"사후 판정"** 되는 것으로 나눈다.

| 구분 | 규칙 | 시점 |
|---|---|---|
| **사전 차단** | 거래 불가 종목 · 종목 편입한도 · 섹터 한도 · 소형주 합산 한도 | 주문 접수 전 |
| **사후 판정** | 주간 회전율 · 관리 점수 | 일·주 단위 배치 |

> **핵심 원칙 — 사전 차단은 주문을 거부하고, 사후 판정은 주문을 막지 않는다.**
> 회전율은 "너무 안 사고팔았다"는 판정이라 주문 시점에 막을 수가 없다.

## 2. 거래 불가 종목 (사전 차단)

### 2.1 판정 기준

| # | 조건 | 데이터 소스 | 갱신 주기 |
|---|---|---|---|
| 1 | 유가증권·코스닥 상장 **보통주**가 아님 (우선주·ETF·ETN·리츠·스팩 제외) | pykrx 종목 마스터 | 일 1회 |
| 2 | **5일 평균 거래대금 30억 이하** | pykrx OHLCV 거래대금 | 일 1회 |
| 3 | 신규상장·재상장 후 **6영업일 미만** | pykrx 상장일 | 일 1회 |
| 4 | 투자주의 / 경고 / 위험 / 투자주의환기 / **관리종목** | KRX 시장경보·관리종목 | 일 1회 |
| 5 | **시가총액 1,000억 미만** | pykrx 시가총액 | 일 1회 |

### 2.2 매수·매도 비대칭 ★

> **위 조건들은 "매수 불가" 조건이다. 매도는 언제나 허용한다.**

이미 보유 중인 종목이 대회 기간 중 관리종목으로 지정되거나 거래대금이 말라붙으면
매수는 막히지만 **팔 길은 열어둬야 한다.** 막으면 참가자가 물린 채 대회를 끝내야 한다.

### 2.3 화면 표현 (타임폴리오 방식)

- 종목 **검색 결과에 노란색 배경**으로 거래 불가임을 미리 알린다
- 그래도 선택하면 **에러 메시지**를 띄운다
- 에러 메시지에 **어느 조건에 걸렸는지**를 명시한다
  (예: "5일 평균 거래대금 12.4억으로 기준 30억 미만입니다")

> v1.0 은 주문 실패 시 이유를 두루뭉술하게 반환하는 곳이 있었다.
> 대회는 규칙이 많으므로 **어느 규칙에 걸렸는지를 반드시 특정**해야 한다.

## 3. 편입 한도 (사전 차단)

### 3.1 종목별 한도

| 기본 | 예외 |
|---|---|
| 순자산 대비 **15% 이하** | 삼성전자(005930) **40%** · SK하이닉스(000660) **30%** |

예외 한도는 `Contest.rule_set.position_limit_exceptions` 에 둔다.
**대회마다 다르게 줄 수 있어야 한다** — 타임폴리오도 SK하이닉스 예외를
2026-07-01 부터 적용했다(중간에 규칙이 바뀐 사례).

### 3.2 섹터 한도

```
허용 비중 = max( 시장 섹터 비중 × 2, 10% ← 시장 비중이 5% 이하인 섹터만 )
```

| 예시 | 시장 비중 | 허용 |
|---|---|---|
| 소재 | 10% | 20% |
| 에너지 | 2% | 10% (2×2=4% 가 아니라 하한 10% 적용) |

- 섹터는 **KRX 업종분류**를 쓴다. GICS 는 유료라 사용 불가 → 문서·화면에 명시.
- 시장 섹터 비중은 **대회 시작 시점에 고정**한다(→ [F-02](F-02-대회-도메인.md) 3.4).

### 3.3 소형주 합산 한도

```
시총 1조 미만 종목들의 합산 비중 ≤ 30%
(시총 1,000억 미만은 애초에 편입 불가 → 2장 조건 5)
```

### 3.4 가격 변동에 의한 초과는 허용한다 ★

> *"편입한도는 주문시 자동 체크되며, 가격변동으로 인한 편입한도 초과는 일시적으로 허용되지만,
> 편입한도 초과가 발생할 경우 참가자는 이를 해소하기 위해 적극적으로 노력해야 하며
> 지속 위반시에는 수상에서 제외될 수 있습니다."*

이 규칙의 구현 의미는 명확하다.

| | 처리 |
|---|---|
| **주문 시점** | 체결 후 예상 비중이 한도를 넘으면 **거부** |
| **보유 중 주가 급등으로 한도 초과** | **강제 매도하지 않는다.** 경고만 표시 |
| **초과 상태에서 추가 매수** | 거부 |
| **초과 상태에서 매도** | 허용 (해소 행위이므로) |
| **지속 위반** | 일별 스냅샷에 위반일수를 누적 → 운영자가 Admin 에서 확인·판단 |

**자동 실격 처리는 하지 않는다.** "적극적으로 노력해야 한다"는 정성 판단이라
자동화하면 억울한 실격이 나온다. 운영자에게 근거 데이터를 주는 선까지가 시스템 역할이다.

## 4. 검증 순서와 응답

### 4.1 검증 파이프라인

```
주문 입력
  │
  ├─ ① 대회 상태 검증      대회가 ONGOING 인가 · 참가 상태가 APPROVED 인가
  ├─ ② 거래 시간 검증      영업일 09:00~15:30 인가 (아니면 PENDING_OPEN)
  ├─ ③ 종목 검증           거래 불가 종목인가 (매수만)
  ├─ ④ 비중 환산           주문 비중(%) → 수량
  ├─ ⑤ 잔고 검증           현금 ≥ 체결예상금액 + 수수료 (매수) / 보유수량 (매도)
  ├─ ⑥ 편입 한도 검증      체결 후 예상 비중이 한도 이내인가 (매수만)
  │                        · 종목별 한도
  │                        · 섹터 한도
  │                        · 소형주 합산 한도
  └─ ⑦ 접수 → 체결 시도
```

**하나라도 실패하면 즉시 중단하고 그 이유를 반환한다.**
여러 규칙에 동시에 걸렸어도 **첫 번째 것만** 알린다 — 한꺼번에 다 보여주면
참가자가 무엇부터 고쳐야 할지 모른다.

### 4.2 응답 형식

v1.0 의 필드 단위 에러 패턴(`{"field": ..., "error": ...}`)을 확장한다.

```jsonc
{
  "ok": false,
  "rule": "POSITION_LIMIT",           // 어느 규칙인가
  "field": "weight_pct",              // 어느 입력칸에 표시할까
  "message": "삼성전자 편입 비중이 42.1% 가 되어 한도 40% 를 초과합니다.",
  "detail": {                         // 화면이 보조 정보로 쓸 수 있게
    "current_pct": 38.5,
    "after_pct": 42.1,
    "limit_pct": 40.0,
    "max_additional_krw": 15230000    // "최대 얼마까지 살 수 있는가"
  }
}
```

> **`max_additional_krw` 가 중요하다.** "안 됩니다"만 말하면 참가자가
> 비중을 바꿔가며 여러 번 시도한다. **"여기까지는 됩니다"를 함께 알려준다.**
> 이게 벤치마크 결함 ②(주문 창에 정보가 부족함)에 대한 대응이기도 하다.

## 5. 주간 회전율 (사후 판정)

### 5.1 산식

```
주간 회전율(%) = (기간 내 매수총액 + 매도총액) / 기간 평균 운용금액 × 0.5 × 100
```

- 기준: **주간 5% 이상 유지**
- 위반 **최대 3회 허용**, **4회 위반 시 자동 정지**(실격)
- 주(week)는 **월요일 00:00 ~ 일요일 24:00 KST**

### 5.2 "예상 위반"과 "확정 위반" ★

타임폴리오 화면이 둘을 나눠 보여준다. 이유가 있다.

| 구분 | 의미 |
|---|---|
| **확정 위반** | 지난 주들까지의 위반 횟수. 더 이상 변하지 않음 |
| **예상 위반** | 확정 위반 + **이번 주 현재 시점 기준** 위반 여부 |

> *"새로운 주가 시작하는 월요일 아침 장시작 전에는 매매가 있을 수 없으므로
> 금주의 예상값은 1회 위반으로 보이는 게 정상입니다."*

이 안내 문구를 **화면에 그대로 넣는다.** 안 그러면 월요일마다 문의가 들어온다.

### 5.3 계산 방식

일별 스냅샷(→ [F-05](F-05-랭킹-정산-스냅샷.md))에서 집계한다.

```sql
-- 개념
주간_매수총액 = SUM(체결금액) WHERE side='BUY'  AND 해당 주
주간_매도총액 = SUM(체결금액) WHERE side='SELL' AND 해당 주
주간_평균운용금액 = AVG(daily_snapshot.total_asset) WHERE 해당 주
```

- 계산은 **pg_cron 일배치**가 매일 장 마감 후 갱신한다.
  실시간 계산은 참가자가 늘면 무너진다(v1.0 결함 D-3 의 교훈: 전 회원 전 포지션 매번 재계산).
- 화면에는 "금주 회전율 2.4%" 처럼 현재 시점 값을 보여준다.

### 5.4 자동 정지 처리

4회 위반 시 `Participation.status = DISQUALIFIED`, `is_ranked = False`.
**계좌·주문 이력은 그대로 둔다.** 랭킹에서만 빠진다.
운영자는 Admin 에서 되돌릴 수 있다.

## 6. 관리 점수 (사후 판정)

수익률만으로 순위를 매기면 "한 종목에 몰빵해서 운 좋게 오른 사람"이 이긴다.
타임폴리오는 이를 막기 위해 **관리 점수**를 함께 본다.

### 6.1 두 축

| 축 | 감점 | 가점 |
|---|---|---|
| **수익 분산** | 총 수익 중 일부 종목의 수익 비중이 클수록 | 수익 종목이 많을수록 |
| **포트 분산** | 포트폴리오 비중이 일부 종목에 집중될수록 | 다양한 종목에 분산 투자할수록 |

### 6.2 산식 설계 (v2.0 제안)

타임폴리오는 산식을 공개하지 않았다. 우리는 **허핀달 지수(HHI)** 기반으로 정의한다.
집중도를 재는 표준적인 지표이고 계산이 단순하다.

```
포트 집중도 HHI_port = Σ (종목별 평균 비중)²          # 0 ~ 1, 낮을수록 분산
수익 집중도 HHI_pnl  = Σ (종목별 수익 / 총수익)²      # 총수익 > 0 인 경우만

포트 분산 점수 = (1 - HHI_port) × 100
수익 분산 점수 = (1 - HHI_pnl)  × 100 × min(수익종목수 / 5, 1)

관리 점수 = 포트 분산 점수 × 0.5 + 수익 분산 점수 × 0.5
```

- `종목별 평균 비중` 은 **일별 스냅샷의 평균**이다. 종료 시점 한 장면이 아니다.
  (마지막 날만 분산시켜 점수를 따는 꼼수 방지)
- 총수익이 0 이하면 수익 분산 점수는 0.
- `min(수익종목수/5, 1)` 은 "수익 종목이 많을수록 가점" 조항의 반영.

> **이 산식은 v2.0 의 제안이며 확정이 아니다.**
> 타임폴리오도 *"대회 운영 과정에서 관리 점수 산출 항목이나 가중치 등은 변경될 수 있습니다"*
> 라고 명시했다. 우리도 `Contest.rule_set` 에 가중치를 두어 **대회별로 조정 가능**하게 한다.
> 1회 대회를 돌려보고 조정하는 것을 전제로 한다.

### 6.3 상대평가

> *"A+ 를 부여하는 절대적인 점수 컷트라인은 없고, 대회별로 상대평가 됩니다."*

- 참가자별 원점수 → **백분위(percentile)** 로 변환
- 최종 점수 = 수익 점수 백분위 × 0.7 + 관리 점수 백분위 × 0.3 (가중치는 `rule_set`)
- 등급(A+ ~ F)은 최종 점수 백분위로 구간을 나눠 부여

## 7. 규칙 위반 화면

타임폴리오는 "가이드라인 위반" 탭과 상단 가이드라인 표를 둔다. 우리도 동일하게.

| 가이드라인 | 기준 | 현재 | 비고 |
|---|---|---|---|
| 종목별 한도 | 15% (삼전 40%) | 12.4% | 주문 시 사전 차단 |
| 섹터별 한도 | max(시장섹터 2배, 10%) | 하단 섹터 표 참조 | 가격 변동에 의한 일시적 초과 허용 |
| 시총 1조 미만 비중 | 30% 이하 | 0.0% | |
| 주간 회전율 | 매주 5% 이상 유지 | **금주 2.4%** | 지속 위반 시 수상 제외 가능 |
| 주간회전율 위반 | 위반 3번까지 허용 | 금주 제외(확정) 누적 1번 | 4번 이상 순위·시상 제외 |
| | 4번 이상 순위/시상 제외 | 금주 포함(예상) 누적 2번 | |

위반 상태는 **빨간색**으로 강조한다.
