> **문서 버전** v2.0 · **분류** 기능=개선 · 구현=재작성

## 1. v1.0 → v2.0 변경 요약

| 항목 | v1.0 | v2.0 |
|---|---|---|
| 모델 | `member` 테이블 직접 정의 | **Django `AbstractUser` 상속** |
| 비밀번호 | bcrypt 직접 구현 | Django 기본 (PBKDF2) |
| 세션 | Flask 서명 쿠키 7일 | Django 세션 (DB 백엔드) |
| **현금** | **`member.asset` 단일 칸** | **`Account.cash` — 모드별 계좌로 분리** ★ |
| 권한 | `email == "admin@admin.com"` 하드코딩 | `is_staff` / `Group` |

**가장 큰 변화는 현금의 위치다.** → [F-00 모드 체계](F-00-모드체계와-범위경계.md) 2.1

> **Django 관점** — FastAPI 에서는 회원 모델·해싱·세션을 직접 만들었다.
> Django 는 `AbstractUser` 를 상속하면 이 셋이 전부 딸려온다.
> 중요한 건 **프로젝트 첫 마이그레이션 전에 커스텀 User 를 정하는 것**이다.
> 나중에 바꾸려면 매우 번거롭다. `AUTH_USER_MODEL = "accounts.Member"` 를
> `settings.py` 에 처음부터 박아둔다.

## 2. 회원 모델

| 필드 | 비고 |
|---|---|
| `username` | 로그인 ID |
| `email` | UNIQUE |
| `password` | Django 해싱 |
| `display_name` | 기본 표시명 (대회에서는 별칭을 따로 씀) |
| `avatar` | 프로필 이미지 (선택) |
| `is_staff` / `is_superuser` | Django Admin 접근 |
| `date_joined` / `last_login` | Django 기본 |

**`asset` 컬럼은 없다.** 현금은 전부 `Account` 에 있다.

## 3. 가입 흐름

```
가입 폼 제출
  ├─ 검증 (필드 단위 에러 반환 — v1.0 패턴 승계)
  ├─ Member 생성
  ├─ 연습 계좌 3개 자동 생성  ← v2.0 신규
  │    · Account(PRACTICE_STOCK,  cash=1억)
  │    · Account(PRACTICE_CRYPTO, cash=1억)
  │    · Account(PRACTICE_ALT,    cash=1억)
  └─ 즉시 로그인 처리 (v1.0 동작 승계)
```

### 3.1 필드 단위 에러 (v1.0 패턴 승계)

v1.0 은 `{"field": "email", "error": "..."}` 형태로 반환해 프론트가
해당 입력칸에 표시했다. 좋은 설계라 유지한다.

Django Form / DRF Serializer 의 에러 구조가 이미 이 모양이다.

```jsonc
{ "email": ["이미 사용 중인 이메일입니다."], "password": ["8자 이상이어야 합니다."] }
```

HTMX 로 폼을 부분 갱신할 때 이 구조를 그대로 템플릿에 넘긴다.

## 4. 인증 방식

| 항목 | 값 |
|---|---|
| 방식 | 세션 쿠키 (Django 기본) |
| 저장소 | **DB 세션 백엔드** — 서버리스라 파일·메모리 세션 불가 |
| 유효기간 | 7일 (`SESSION_COOKIE_AGE`, v1.0 승계) |
| CSRF | Django 기본. HTMX 요청에 `X-CSRFToken` 헤더 포함 |
| Open API | 별도 — Bearer API Key (→ [F-13](F-13-OpenAPI.md)) |

> **HTMX + CSRF** — HTMX 는 폼이 아닌 요청도 보내므로 CSRF 토큰이 자동으로 안 붙는다.
> `hx-headers='{"X-CSRFToken": "..."}'` 를 `<body>` 에 한 번 걸어두면 전 요청에 상속된다.
