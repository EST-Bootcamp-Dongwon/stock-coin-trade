## 무엇을 만드는가

동아리 **모의투자 대회 플랫폼**. 벤치마크는 `contest.timefolio.net`.
v1.0(강사님 원본 `08a23a7`)의 기능 20종을 전부 살리면서 대회 도메인을 얹는다.

## 대회 규칙 (1차 범위)

| 규칙 | 값 |
|---|---|
| 종목 편입 한도 | 15% (삼성전자 40% · SK하이닉스 30%) |
| 섹터 한도 | max(시장 섹터 비중 × 2, 10%) — **KRX 업종분류** (GICS 아님) |
| 소형주 합산 | 시총 1조 미만 30% 이하 |
| 거래 불가 | 5일 거래대금 30억 이하 · 시총 1000억 미만 · 관리종목 · 신규상장 6영업일 |
| 주간 회전율 | 5% 이상. 위반 3회 허용, 4회 실격 |
| 거래 비용 | 수수료 10bp · 매도세 20bp |
| 주문 입력 | **수량이 아니라 순자산 대비 %** |
| 최종 평가 | 수익 점수 70% + 관리 점수(수익분산·포트분산) 30%, **상대평가** |

## 기술 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 백엔드 | Django + DRF | 대회 운영 화면을 Django Admin 이 해결 · drf-spectacular 가 API 문서 자동 생성 |
| 프론트 | HTMX + Alpine + Tailwind | 대회 화면은 대부분 표·폼. React 대비 코드량이 훨씬 적다 |
| DB | Supabase Postgres | |
| 스케줄러 | **pg_cron** (잡 14종) | APScheduler 는 서버리스에서 죽고, Vercel Hobby cron 은 하루 1회 |
| **호가** | **KIS Developers 실호가** | 대회 체결의 근거. 초당 5건 제한 → 우선순위 폴링 |
| **종목 데이터** | **pykrx 일배치** | 시총·거래대금·관리종목·업종 |
| **캐시** | **Supabase Postgres 테이블** | 서버리스라 프로세스 메모리는 무의미. 비용 0 |
| 벡터 DB | Qdrant → **pgvector** | 이미 쓰는 DB 안. `:memory:` 소실 문제 해결 |
| 배포 | Vercel + Docker Compose | AWS 제거 |

## 체결 방식 (절충안) ★

> 주문은 **즉시 접수·즉시 체결 시도**. 상대호가 잔량으로 채울 수 있는 만큼 그 자리에서
> 체결하고, 남은 잔량은 `PARTIAL` 로 남아 **시세 폴링 잡(5초)이 시장 체결을 추종**한다.

비동기 워커 없이 타임폴리오 체결 규칙을 재현한다.
포기: 시간분할 주문 · 과주문 후 대기 → v2.1.

## 관통 원칙 3가지

1. **죽은 코드를 남기지 않는다** — 기능을 만들면 진입점을 만든다
2. **화면에 보이지 않는 사실은 없는 것과 같다** — 파생 호가·시뮬레이션 가격을 배지로 표시
3. **서버리스 전제를 처음부터 지킨다** — 요청을 넘어서 사는 상태는 전부 DB
