# F-07. 코인 연습 모드

> **문서 버전** v2.0 · **분류** 기능=살림 · 구현=수정포팅
> **v1.0 대응** 1-2 코인거래 (`crypto.py` 314줄 · `order.js` 396줄)
> **모드** `PRACTICE_CRYPTO` — 24시간 거래. 대회 대상 아님(1차)

---

## 1. 승계하는 것

| 기능 | 처리 |
|---|---|
| 업비트 WebSocket 실시간 시세 | **유지.** 브라우저 ↔ 업비트 직접 연결 + nginx 중계 경로 (`proxy_set_header Origin "";`) |
| 국내 4대 거래소 시세 비교 (업비트·빗썸·코인원·코빗) | 유지. 개별 실패는 `null` 로 흘려보냄 (`_fetch_price_safely` 승계) |
| 매수 — 원화 금액 입력 → 수량 산출 (소수점 8자리) | 유지 |
| 매도 — 수량 입력 → 매수원금 비율 차감 | 유지 |
| 평단 재계산 · 행 잠금(`SELECT FOR UPDATE`) | 유지 (→ [F-03](F-03-주문-체결엔진.md) 7장) |
| Lightweight Charts 코인 차트 | 유지 |
| ⭐ 관심코인 | **`localStorage` → `Watchlist` 테이블로 승격** |

---

## 2. 신설하는 것 ★

### 2.1 코인 주문 이력 (결함 D-4 해소)

> v1.0 은 주식(`stock_order`)·대체자산(`alternative_order`)에는 주문 이력이 있는데
> **코인만 없었다.** `hold_crypto`(현재 보유)만 있어 체결 내역을 복원할 수 없었다.

v2.0 은 통합 `Order` 테이블에 `asset_class="CRYPTO"` 로 기록한다.
이것이 있어야 [F-10 거래이력](F-10-거래이력.md)의 자산군 통합 조회가 가능하다.

### 2.2 코인 랭킹 재정의 (결함 D-3 해소)

| | v1.0 | v2.0 |
|---|---|---|
| 소스 | CoinMarketCap Pro API (USD Top 100) | **업비트 KRW 마켓 24시간 거래대금** |
| 갱신 | 매시 `TRUNCATE` 후 재적재 | 매시 **upsert** |
| 사용처 | **없음** — 스케줄러가 매시 채우기만 함 | **코인 화면에 실제로 표시** |
| 통화 정합성 | USD 랭킹 ↔ KRW 거래 (불일치) | KRW 기준으로 통일 |

CoinMarketCap 키 의존도 사라진다.

## 3. 계좌·수수료

| 항목 | 값 |
|---|---|
| 계좌 | `Account(PRACTICE_CRYPTO)`, 초기 1억 |
| 수수료 | **0.05% 매수·매도 양방향** (업비트 기준) |
| 세금 | 없음 |
| 거래 시간 | 24시간 |

v1.0 은 `member.asset` 을 주식과 공유했다. v2.0 은 코인 전용 계좌를 쓴다.
**"코인으로 얼마 벌었나"를 독립적으로 볼 수 있게 된다.**

## 5. v2.2 확장 여지

`Contest.asset_class = "CRYPTO"` 로 **코인 대회**를 열 수 있다.
1차에는 만들지 않지만 필드는 미리 있다.

코인 대회를 열 때 추가로 필요한 것:
- 24시간 거래이므로 "일별 정산" 시점 정의 (KST 00:00 기준 제안)
- 변동성이 커서 편입 한도를 주식과 다르게 잡아야 함
- 상장폐지·거래유의 종목 처리
