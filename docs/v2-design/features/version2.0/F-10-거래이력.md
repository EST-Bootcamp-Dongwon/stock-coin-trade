# F-10. 거래이력

> **문서 버전** v2.0 · **분류** 기능=개선 · 구현=재작성
> **v1.0 대응** 1-5 거래이력 (`trade-history.js` · AG Grid)

---

## 1. v1.0 의 한계

기능 자체는 훌륭했다 — AG Grid 로 정렬·필터·페이지네이션·빠른검색·CSV 내보내기.
문제는 **범위**였다.

| 문제 | 상세 |
|---|---|
| **주식만 보여준다** | `GET /api/stocks/orders/history` 하나만 호출. "내 거래이력"이라는 이름과 맞지 않음 |
| 대체자산 이력이 연결 안 됨 | `alternative_order` 테이블은 있는데 이 화면에 안 붙어 있음 |
| **코인 이력은 아예 없음** | 테이블 자체가 없었다 (결함 D-4) |
| 클라이언트 페이지네이션 | 최대 1000건을 한 번에 내려받음 |

## 2. v2.0 설계

### 2.1 통합 조회

[F-03](F-03-주문-체결엔진.md) 9.1 에서 `Order` 테이블을 자산군 통합으로 만들었으므로
**한 번의 쿼리로 전 자산군 이력**이 나온다.

```
GET /api/orders?account=&asset_class=&side=&symbol=&from=&to=&page=
```

### 2.2 필터

| 필터 | 값 |
|---|---|
| **계좌** | 전체 / 주식연습 / 코인연습 / 대체자산연습 / 대회별 |
| 자산군 | 전체 / 주식 / 코인 / 대체자산 |
| 구분 | 전체 / 매수 / 매도 |
| 종목 | 검색 |
| 기간 | 날짜 범위 |
| **주문 경로** | 웹 / Pine / Open API / 운영자 / 샘플 |
| **상태** | 체결 / 부분체결 / 취소 / 거부 |

### 2.3 컬럼

| 컬럼 | 비고 |

| 종목코드 | |

### 2.4 상단 요약 (v1.0 승계 + 확장)

총 건수 · 총 매수금액 · 총 매도금액 · **총 수수료 · 총 세금 · 실현손익**

> **실현손익 표시가 새로 생긴다.** 매도 시 `(체결가 - 평단) × 수량 - 비용` 을
> `Order` 에 기록해두면 사후 계산 없이 합산할 수 있다.

## 3. AG Grid 를 유지할 것인가 ★

**결론: 서버 사이드 페이지네이션 + HTMX 로 간다. AG Grid 는 걷어낸다.**

| 판단 축 | 근거 |
|---|---|
| 데이터 양 | 대회 1달이면 참가자당 수백 건. 서버 페이지네이션이면 충분 |
| 프로젝트 방침 | 확정 스택이 **HTMX + Alpine + Tailwind**. 무거운 그리드 라이브러리는 방향과 어긋남 |
| 강사님 지침 | "frontend 헤비하지 않게, backend·AI 강조" |
| 잃는 것 | 컬럼 드래그·피벗 같은 고급 기능 |
| 대체 | 정렬·필터·검색·CSV 내보내기는 **서버에서 제공**. 실무적으로 이게 더 정확하다 |

### 3.1 CSV 내보내기

v1.0 은 클라이언트에서 만들었다. v2.0 은 **서버에서 스트리밍 응답**으로 준다.
- 필터 조건이 그대로 반영된다
- 1000건 제한이 사라진다
- **BOM 포함 UTF-8** 로 내보낸다 (v1.0 의 판단 승계 — Excel 한글 깨짐 방지)

## 4. 대회 참가자 이력 공개

[F-05](F-05-랭킹-정산-스냅샷.md) 3.3 의 포트폴리오 공개 정책에 따라
**다른 참가자의 거래 이력도 볼 수 있다** (`Contest.portfolio_visibility` 설정에 따름).

- 공개 시에는 **계좌 잔고·현금은 가리고 종목·수량·시점만** 보여준다
- 벤치마크(타임폴리오)에는 없는 기능이다. 동아리 학습 목적이므로 추가한다
