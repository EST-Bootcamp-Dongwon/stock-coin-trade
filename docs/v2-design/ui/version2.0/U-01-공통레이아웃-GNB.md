## 1. 레이아웃 골격

```
┌─────────────────────────────────────────────────┬────────┐
│  헤더 (GNB)                                       │        │
├─────────────────────────────────────────────────┤  우측   │
│                                                 │ 오프캔버스│
│  콘텐츠                                           │  패널   │
│                                                 │        │
├─────────────────────────────────────────────────┤        │
│  푸터 (교육용 고지)                                 │        │
└─────────────────────────────────────────────────┴────────┘
```

`base.html` 하나가 이 골격을 담고, 모든 페이지가 상속한다.

> **Django 관점** — Next.js 의 `layout.tsx` 에 해당한다.
> Django 는 `{% extends "base.html" %}` + `{% block content %}` 로 같은 일을 한다.
> 중첩 레이아웃이 필요하면 `base.html` → `contest_base.html` → `dashboard.html`
> 처럼 **상속을 한 단계 더** 쌓는다.

## 2. GNB 구조

v1.0 은 `common.js` 의 `navGroups` 배열로 메뉴를 만들었고,
**Pine 화면 2개가 여기 빠져 있었다**(결함 D-2).

v2.0 은 **서버 렌더링**한다. 메뉴 정의를 한 곳에 두고 권한·모드에 따라 거른다.

### 2.1 메뉴 구성

| 1차 | 2차 | 경로 |
|---|---|---|
| **대회** | 대회 목록 | `/contests/` |
| | 내 대회 | `/account/contests/` |
| | *(참가 중이면)* 대회 대시보드 | `/contests/<id>/me/` |
| **연습** | 주식 | `/practice/stock/` |
| | 코인 | `/practice/crypto/` |
| | 대체자산 | `/practice/alternatives/` |
| | **Pine 전략** ★ | `/practice/pine/` |
| **자산** | 전체 자산 | `/portfolio/` |
| | 거래 이력 | `/orders/` |
| **학습** | 학습 홈 | `/learn/` |
| | 투자분석 14레슨 | `/learn/analysis/` |
| | 가이드 (KB · KIS · TradingView · Pine 기초) | `/learn/guides/` |
| **도구** | 물타기 계산기 | `/tools/avg-down/` |
| | 웹 데이터 수집기 | `/tools/web-scraper/` |
| | API 문서 | `/api/docs/` |
| *(우측)* | 프로필 · API 키 · 로그아웃 | `/account/...` |

★ = v1.0 에서 메뉴에 없던 화면 (결함 D-2 해소)

### 2.2 진행 중 대회 강조

참가 중인 대회가 있으면 **GNB 에 상시 배지**를 띄운다.

```
[대회 ▾]  ← RFM 1회 · D-12 · 7위   (배지)
```

장중에는 순위 변동을 배지로 알린다. 대회가 서비스의 중심임을 계속 상기시킨다.

### 2.3 비로그인 처리

v1.0 은 오프캔버스 메뉴를 **잠금 화면으로 대체**했다. 이 방식을 유지하되 개선한다.

| v1.0 | v2.0 |
|---|---|
| 잠금 화면만 표시 | **"로그인하면 이용할 수 있습니다" + 로그인 버튼 + 무엇을 할 수 있는지 3줄 요약** |

## 3. 우측 오프캔버스 패널

v1.0 의 핵심 UI 다. 전 화면 공통으로 붙어 있다. **그대로 유지한다.**

### 3.1 탭 구성

| 탭 | 내용 | 문서 |
|---|---|---|
| **AI 분석** | 분석 범위 선택 → Claude 스트리밍 응답 · RAG 근거 접이식 | [F-14](../../features/version2.0/F-14-AI분석.md) |
| **지식 검색** | 시맨틱 검색 · 유사도 색상 | [F-15](../../features/version2.0/F-15-지식검색-RAG.md) |
| **데이터셋** | 문서 목록 · 지식 추가 | [F-15](../../features/version2.0/F-15-지식검색-RAG.md) |
| **KRX 뉴스** | 하단 고정 260px 영역 → **독립 탭으로 승격** | [F-16](../../features/version2.0/F-16-시장데이터-파이프라인.md) 7장 |

### 3.2 v2.0 변경점

| 항목 | v1.0 | v2.0 |
|---|---|---|
| AI 분석 컨텍스트 | **DOM 스크래핑** | **서버가 조립** ★ |
| 분석 범위 | 코인/주식/전체 | + **내 포트폴리오** · **대회 맥락** |
| KRX 뉴스 위치 | AI 탭 하단 고정 260px | **독립 탭** (좁아서 읽기 불편했다) |
| 인증 | 없음 | **로그인 필수 + 사용량 제한** |

### 3.3 화면 맥락 전달

DOM 스크래핑을 버리는 대신, **현재 보고 있는 화면의 맥락을 서버에 알린다.**

```html
<body data-context-type="contest" data-context-id="{{ contest.id }}">
```

AI 분석 요청 시 이 값을 함께 보내면 서버가 알맞은 컨텍스트를 조립한다.
**화면 구조가 바뀌어도 깨지지 않는다.**

## 4. 공통 컴포넌트

| 컴포넌트 | 용도 |
|---|---|
| **토스트** | `HX-Trigger: {"toast": {...}}` 로 발행 (→ [01-HTMX 규약](01-HTMX-부분갱신-규약.md) 4장) |
| **종목 검색 모달** | 전 화면 공통. 대회에서는 거래 불가 종목을 **노란색**으로 표시 |
| **확인 다이얼로그** | 계좌 초기화·주문 취소 등 |
| **숫자 표시 규칙** | 원화 3자리 콤마 · 등락률 소수 2자리 · **상승 빨강 / 하락 파랑** (국내 관행) |
| **로딩 스켈레톤** | 첫 로드 시 |
| **모드 배지** | 현재 계좌가 어느 모드인지 항상 표시 ★ |

### 4.1 모드 배지 ★

계좌가 4개로 늘어나므로 **지금 어느 계좌를 보고 있는지**가 혼동되기 쉽다.

```
[대회: RFM 1회]  [주식 연습]  [코인 연습]  [대체자산 연습]
```

- 색으로 구분 (대회 = 강조색, 연습 = 중성색)
- 거래 화면 상단에 **고정**
- 대회 계좌는 "실제 규칙 적용 중"임을 함께 표시
