## 1. 라우팅 원칙

### 1.1 URL 은 도메인 언어로 쓴다

v1.0 은 정적 파일 경로가 곧 URL 이었다 (`/trade/order.html`, `/trade/hold.html`).
v2.0 은 Django URL 이므로 **자원 중심**으로 다시 짠다.

| v1.0 | v2.0 | 이유 |
|---|---|---|
| `/trade/order.html` | `/practice/crypto/` | "order" 가 코인 거래를 뜻하는지 알 수 없다 |
| `/trade/stock.html` | `/practice/stock/` | |
| `/trade/hold.html` | `/portfolio/` | |
| `/trade/history.html` | `/orders/` | |
| `/trade/avg-down.html` | `/tools/avg-down/` | |
| `/analysis.html` | `/learn/analysis/` | |
| `/ai-sheet.html` | `/tools/web-scraper/` | 개명 (→ [F-18](../../features/version2.0/F-18-웹데이터-수집기.md)) |
| `/openapi.html` | `/api/docs/` | drf-spectacular 자동 생성 |

### 1.2 계층 5개

```
/                      홈
/contests/...          대회
/practice/...          연습 (주식·코인·대체자산)
/portfolio/ /orders/   자산·이력 (모드 공통)
/learn/ /tools/        학습·도구
/account/              계정
/admin/                Django Admin
```

### 1.3 Django URL 관점

> **Django 관점** — FastAPI 는 데코레이터에 경로를 직접 쓴다(`@app.get("/contests/{id}")`).
> Django 는 `urls.py` 에 **경로와 뷰를 분리해 등록**하고, `name=` 을 붙여
> 템플릿에서 `{% url 'contest:detail' contest.id %}` 로 역참조한다.
>
> **URL 을 템플릿에 하드코딩하지 않는다.** 경로가 바뀌어도 `urls.py` 만 고치면 된다.
> 앱별로 `app_name` 을 두어 네임스페이스를 나눈다 (`contests:detail`, `practice:stock`).

## 3. 대회 대시보드 (#9) 구성 ★

가장 중요한 화면이다. 타임폴리오 캡처를 기준으로 구성한다.

```
┌─ 상단 요약 바 ──────────────────────────────────────┐
│ 대회 선택▾  기준일  ⟳   |  KOSPI 3,182 +0.03  KOSDAQ 802 -8.03 │
└──────────────────────────────────────────────────┘
┌─ 차트 2종 ──────────────────┬──────────────────────┐
│ Intraday Return (%)         │ Daily NAV              │
│ Portfolio · KOSPI · KOSDAQ  │ Portfolio · KOSPI · KOSDAQ │
└─────────────────────────────┴──────────────────────┘
┌─ 가이드라인 표 ──────────────┬─ 섹터 비중 막대 ────────┐
│ 항목 | 기준 | 현재 | 비고      │ Market vs Portfolio    │
│ 종목별 한도 · 섹터 한도       │                        │
│ 시총1조미만 · 주간회전율      │                        │
│ 회전율 위반                  │                        │
└─────────────────────────────┴──────────────────────┘
┌─ 미접수 / 에러 주문 ─────────────────────────────────┐
│ 종목코드 | 종목명 | 조건 | 시간 | 상태 | 정정 | 취소      │
└──────────────────────────────────────────────────┘
┌─ 주문 타겟                              [+ 신규 주문] ┐
│ 코드 | 종목명 | 현재가 | 당일% | 비중%(전일/주문/미체결/타겟) │
└──────────────────────────────────────────────────┘
┌─ 보유 잔고 ──────────────────────────────────────────┐
│ 코드 | 종목명 | 현재가 | 당일% | 잔고 | 비중% | 평가액       │
│      | 평단가 | 손익률% | 손익                            │
└──────────────────────────────────────────────────┘
┌─ 탭 ─────────────────────────────────────────────┐
│ 가이드라인 위반 | 도움말 | 섹터 비중 | 일별 체결합         │
│ 주문 내역 | 진입/청산 내역 | 섹터 유니버스                 │
└──────────────────────────────────────────────────┘
```

### 3.1 v1.0 대비 개선 (벤치마크 결함 ② 대응)

타임폴리오 신규 주문 창에는 **현재가·내 평단이 없다.** 우리는 넣는다.

```
[신규 주문]
 종목: 삼성전자 (005930)          현재가 74,300 (+4.8%)
 ┌─────────────────────────────────────────┐
 │ 내 보유: 100주 · 평단 71,200 · 손익 +4.35%   │  ← v2.0 신규
 │ 현재 비중 7.2% / 한도 40.0%                │  ← v2.0 신규
 │ 최대 추가 매수: 15,230,000원                │  ← v2.0 신규
 └─────────────────────────────────────────┘
 [매수] [매도]
 주문 비중(%): [___]     ← 슬라이더 동반
 [상대호가] [자기호가] [지정가] [STOP]
 상대호가(1~10): [5]
 [즉시 실행] [시간 분할(v2.1)]
 ──────────────────────────────────────
 예상 체결금액 7,430,000 · 수수료 7,430 · 정산 7,437,430
 [주문 제출]
```

## 4. 반응형 정책

| 폭 | 처리 |
|---|---|
| ≥ 1280px | 2단 레이아웃 (차트 나란히 · 표 전체 컬럼) |
| 768~1279px | 1단. 차트 세로 배치 |
| < 768px | **표는 카드 리스트로 전환.** 컬럼 우선순위에 따라 접기 |

**모바일에서 대회 주문은 가능해야 한다.** 장중에 이동 중에도 대응할 수 있어야 한다.
반면 Top Pick 매트릭스·산점도 같은 분석 화면은 **가로 스크롤 + 데스크톱 권장 안내**로 처리한다.

## 5. 접근 제어

| 구분 | 규칙 |
|---|---|
| 비로그인 | 홈 · 대회 목록/상세/랭킹 · 로그인/가입 · API 문서만 |
| 로그인 | 연습·학습·도구·자산·이력 |
| 대회 참가자 | 해당 대회의 대시보드·주문 |
| 대회 종료 후 | 읽기 전용 (주문 버튼 비활성 + 사유 표시) |
| 운영자 | Django Admin |

> **v1.0 은 비로그인 시 GNB 오프캔버스를 잠금 화면으로 대체**했다.
> 이 방식은 유지하되, **잠긴 이유와 로그인 링크를 명확히** 보여준다.
