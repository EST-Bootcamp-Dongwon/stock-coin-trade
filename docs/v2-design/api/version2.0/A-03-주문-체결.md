## 1. `POST /api/orders` — 주문

### 1.1 요청 — 대회 모드

```jsonc
{
  "account_id": 12,
  "symbol": "005930",
  "side": "BUY",                  // BUY | SELL
  "weight_pct": 5.0,              // 순자산 대비 % ★ 수량이 아니다
  "order_type": "COUNTER",        // COUNTER(상대호가) | OWN(자기호가) | LIMIT | STOP
  "price_level": 5,               // COUNTER·OWN 일 때 1~10
  "limit_price": null,            // LIMIT 일 때
  "stop_price": null,             // STOP 일 때
  "execution_mode": "IMMEDIATE"   // IMMEDIATE (SLICED 는 v2.1)
}
```

### 1.2 요청 — 연습 모드

```jsonc
{
  "account_id": 3,
  "symbol": "005930",
  "side": "BUY",
  "qty": 100,                     // 또는 amount_krw
  "order_type": "MARKET",         // MARKET | LIMIT
  "limit_price": null
}
```

**코인은 `qty` 를 문자열로 보낸다** (소수점 8자리).

### 1.3 응답 — 성공 (201)

```jsonc
{
  "id": 8821,
  "status": "FILLED",             // FILLED | PARTIAL | ACCEPTED | PENDING_OPEN
  "symbol": "005930", "side": "BUY",
  "requested_qty": 100, "filled_qty": 100,
  "avg_fill_price": 74310,
  "gross_amount": 7431000,
  "fee": 7431, "tax": 0,
  "settled_amount": 7438431,      // 매수는 차감액, 매도는 수령액
  "executions": [                 // 호가 단계별 체결 내역
    { "qty": 60, "price": 74300 },
    { "qty": 40, "price": 74320 }
  ],
  "account_after": { "cash": 34911569, "total_asset": 103820000 },
  "filled_at": "2026-08-11T14:23:11+09:00"
}
```

**`executions` 를 함께 주는 이유** — 대회 모드는 호가 잔량을 소진하며 체결하므로
**한 주문에 체결가가 여러 개**다. 평균만 주면 참가자가 "왜 이 가격이지?"를 알 수 없다.

### 1.4 응답 — 규칙 위반 (400)

```jsonc
{
  "ok": false,
  "rule": "POSITION_LIMIT",
  "field": "weight_pct",
  "message": "삼성전자 편입 비중이 42.1% 가 되어 한도 40% 를 초과합니다.",
  "detail": {
    "current_pct": 38.5, "after_pct": 42.1, "limit_pct": 40.0,
    "max_additional_krw": 15230000,
    "max_additional_weight_pct": 1.5
  }
}
```

### 1.5 `rule` 값 목록

| 값 | 의미 |
|---|---|
| `CONTEST_NOT_ONGOING` | 대회가 진행 중이 아님 |
| `NOT_PARTICIPANT` | 참가자가 아님 · 실격 상태 |
| `MARKET_CLOSED` | 거래 시간 아님 (→ `PENDING_OPEN` 으로 접수될 수도) |
| `SYMBOL_NOT_TRADABLE` | 거래 불가 종목 (하위 사유는 `detail.reasons`) |
| `INSUFFICIENT_CASH` | 잔고 부족 |
| `INSUFFICIENT_POSITION` | 보유 수량 부족 |
| `POSITION_LIMIT` | 종목 편입 한도 |
| `SECTOR_LIMIT` | 섹터 한도 |
| `SMALL_CAP_LIMIT` | 소형주 합산 한도 |
| `PRICE_UNAVAILABLE` | 시세 조달 불가 (503) |

### 1.6 `SYMBOL_NOT_TRADABLE` 의 상세

```jsonc
"detail": {
  "reasons": [
    { "code": "LOW_TURNOVER", "message": "5일 평균 거래대금 12.4억 (기준 30억)" },
    { "code": "SUPERVISED",   "message": "관리종목" }
  ]
}
```

**어느 조건에 걸렸는지 특정한다.** v1.0 은 실패 이유가 두루뭉술한 곳이 있었다.

## 2. `POST /api/orders/preview` — 주문 미리보기 ★

**v2.0 신규.** 주문을 내기 전에 비용·한도·예상 체결을 확인한다.

요청은 `POST /api/orders` 와 동일. 응답은 **체결하지 않고 계산만** 한다.

```jsonc
{
  "ok": true,
  "estimated": {
    "qty": 100,
    "avg_price": 74310,           // 호가 잔량 기준 예상 평균 체결가
    "gross_amount": 7431000,
    "fee": 7431, "tax": 0,
    "settled_amount": 7438431,
    "fully_filled": true,          // 호가 잔량으로 전량 체결 가능한가
    "expected_partial_qty": 0
  },
  "limits": {
    "position": { "after_pct": 10.7, "limit_pct": 15.0, "ok": true },
    "sector":   { "after_pct": 24.1, "limit_pct": 32.0, "ok": true },
    "small_cap":{ "after_pct":  0.0, "limit_pct": 30.0, "ok": true }
  },
  "account_after": { "cash": 34911569 }
}
```

**이 엔드포인트가 벤치마크 결함 ②(주문 창에 정보가 없음)에 대한 답이다.**
주문 모달이 입력값을 바꿀 때마다 이걸 호출해 미리보기를 갱신한다.

> 호출 빈도가 높으므로 **디바운스 500ms** 를 건다. 외부 API 는 호출하지 않고
> 캐시된 호가만 읽는다.

## 3. `GET /api/orders` — 통합 이력

### 3.1 쿼리 파라미터

| 파라미터 | 값 |
|---|---|
| `account` | 계좌 ID (미지정 = 전체) |
| `asset_class` | `STOCK` / `CRYPTO` / `ALT` |
| `contest` | 대회 ID |
| `side` | `BUY` / `SELL` |
| `symbol` | 종목코드 |
| `status` | `FILLED` / `PARTIAL` / `ACCEPTED` / `CANCELLED` / `REJECTED` |
| `source` | `WEB` / `PINE` / `OPENAPI` / `ADMIN` / `DEMO_SEED` |
| `from` · `to` | 날짜 (KST) |
| `page` · `page_size` | 서버 페이지네이션 (기본 20, 최대 100) |

### 3.2 응답

```jsonc
{
  "count": 142, "next": "...", "previous": null,
  "summary": {                     // ★ 필터 조건 전체에 대한 집계
    "total_buy": 520000000, "total_sell": 480000000,
    "total_fee": 520000, "total_tax": 960000,
    "realized_pnl": 3200000
  },
  "results": [ /* 주문 목록 */ ]
}
```

**`summary` 는 현재 페이지가 아니라 필터 전체 기준**이다.
v1.0 은 1000건을 다 받아 클라이언트에서 합산했다. 서버가 계산한다.

## 4. `POST /api/orders/<id>/cancel` — 취소

| 상태 | 결과 |
|---|---|
| `ACCEPTED` · `PARTIAL` · `PENDING_OPEN` | 취소 성공. 잔량 소멸 |
| `FILLED` · `CANCELLED` · `REJECTED` | 409 |

**정정(수정)은 v2.1.** 1차는 취소 후 재주문.

## 5. `GET /api/orders/export` — CSV

- 필터 조건은 `GET /api/orders` 와 동일
- **스트리밍 응답** (`StreamingHttpResponse`) — 건수 제한 없음
- **BOM 포함 UTF-8** (Excel 한글 정상 — v1.0 판단 승계)

## 6. `GET /api/positions` — 보유

```
?account=<id>
```

계좌 스냅샷(`/api/accounts/<id>/snapshot`)에 포함되므로 **화면에서는 대개 그쪽을 쓴다.**
이 엔드포인트는 봇·단순 조회용.

## 7. 멱등성

주문은 **멱등키를 받지 않는다.** 1차 범위에서는 다음으로 충분하다.

| 위험 | 대응 |
|---|---|
| 더블 클릭 | 프론트에서 버튼 비활성화 + HTMX `hx-disabled-elt` |
| 네트워크 재시도 | 브라우저 폼 재제출 방지 (POST 후 프래그먼트 갱신) |
| 봇 중복 호출 | Open API 는 rate limit 으로 통제 |

> 실거래가 아니라 모의투자이고, 중복 주문이 발생해도 취소·재조정이 가능하다.
> 멱등키는 v2.1 에서 Open API 에만 도입을 검토한다.
