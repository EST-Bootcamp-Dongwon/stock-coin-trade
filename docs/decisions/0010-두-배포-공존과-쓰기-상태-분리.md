# ADR-SC-0010 — 두 배포를 공존시키고, 쓰기 상태를 Supabase 로 분리한다

- **상태**: 채택
- **날짜**: 2026-09-12
- **관련**: [ADR-SC-0006](0006-krx-데이터-제3자-제공-금지.md) ·
  [ADR-SC-0008](0008-배포-streamlit-전환과-원격-재구성.md) **(② ③ 을 개정한다)**
- **개정하지 않는 것**: ADR-SC-0008 ④ ⑤(원격 구성 · `gh` 계정 확인)는 **그대로다**

## 맥락

M8 작업 중 사용자가 **화면 완성도**를 문제로 제기했다 — "Streamlit 이라 디자인에
한계가 있는 것 아닌가, Django + Vercel 로 옮기면 CRUD·기능 확장에 유리하지 않나".
동시에 **Supabase 프로젝트를 되살렸다**고 알려 왔다.

ADR-SC-0008 은 2026-09-11 에 Vercel 과 Supabase 를 **둘 다** 버렸다. 그 판단의
전제 셋을 다시 재 보니 **세 개 중 세 개가 바뀌어 있었다.** 한 달 전 문서가 아니라
하루 전 문서인데도 그렇다 — 플랫폼이 움직였고, 우리 운영 방식도 그 사이에 정해졌다.

## 결정

### ① 두 배포를 **공존**시킨다. 이전이 아니라 추가다

| | 역할 | 대상 |
|---|---|---|
| **Streamlit Cloud** | **팀용 정본.** 대회 기간 팀 7명이 매일 여는 화면 | 계속 개발한다 |
| **Django + Vercel** | **확장·쇼케이스.** CRUD 가 늘어나는 기능과 포트폴리오 | 새로 만든다 |

🔒 **Streamlit 을 먼저 끄지 않는다.** 대회가 도는 중이고 Django 는 몇 세션이 걸린다.
그 사이 팀이 쓸 것이 없으면 안 된다. 끄는 시점은 Django 가 **실제로 팀에게 쓰일 때**
다시 판단한다.

### ② 코어를 공유한다 — 렌더러만 둘이다

```
sector/          계산 · 원천 · 스코어링        ← st 없음
dashboard/view.py · explain.py · evidence.py   ← st 없음(evidence 만 얇게 쓴다)
        ├── streamlit_app.py + dashboard/pages/   (렌더러 A)
        └── backend/<새 앱>/                       (렌더러 B)
```

이미 그렇게 갈라 뒀다 — `view.py` 머리주석이 *"`st.*` 가 섞이면 화면 없이 테스트할 수
없다"* 고 적어 둔 그 분리가, 뜻하지 않게 **두 번째 렌더러를 붙일 수 있는 구조**가 됐다.
🔒 **점수·서술을 두 번 구현하지 않는다.** 두 화면이 같은 섹터를 두고 다른 말을 하면
팀원은 어느 쪽이 맞는지 판단할 방법이 없다.

🔴 **`backend/` 의 26,597줄은 재사용 대상이 아니다.** 그것은 *다른 제품*(모의투자
플랫폼 — `accounts`·`contests`·`trading`·`market`)이다. 실제로 물려받는 것은
**`templates/base.html` + `_partials/` + Tailwind `app.css` + HTMX/Alpine 패턴** 이고,
섹터 화면은 새 앱으로 쓴다. 이 점을 흐리면 "이미 다 돼 있다" 는 착시가 생긴다.

### ③ 의존성 분리는 **`api/requirements.txt`** 가 한다. Root Directory 는 **저장소 루트**다

> 🔴 **2026-09-12 개정 — 아래가 확정이다.** 최초 판단("Root Directory = `backend/`")은
> **실측으로 틀렸다.** 원문과 왜 틀렸는지는 이 절 끝에 남긴다.

| 배포 | 읽는 파일 | 조치 |
|---|---|---|
| Streamlit Cloud | 루트 `requirements.txt` | **지금 그대로.** 손대지 않는다 |
| Vercel | **`api/requirements.txt`** (slim) | **이미 있다.** Root Directory 는 **비운다**(저장소 루트) |

**Vercel 이 `api/requirements.txt` 를 실제로 읽는다** — 2026-09-11 프로덕션 빌드 로그가
`Installing required dependencies from api/requirements.txt...` 라고 적는다. 즉 루트
`requirements.txt` 를 Streamlit 에 내주고도 Vercel 쪽 의존성이 **이미 갈려 있었다.**
루트 `.vercelignore` 의 `/requirements.txt` 한 줄이 Streamlit 목록을 번들에서 빼고,
그 결과가 함수 **33.71MB** 다.

#### 🔴 왜 `backend/` 가 아닌가 — 실측 네 가지 (2026-09-12)

| | 저장소 루트 (확정) | `backend/` |
|---|---|---|
| **빌드 산출물** | `λ api/index.py (33.71MB)` · `/` 200 | **`. [0ms]` · 함수 0개** → 전부 404 |
| **의존성** | `api/requirements.txt` (slim) | `backend/requirements.txt`(full) — `pykrx`·`fastembed` 가 pandas·numpy·onnxruntime·matplotlib **260MB+** 를 끌고 온다 |
| **`.vercelignore`** | 적용됨 — `Removed 112 ignored files` | `backend/.vercelignore` 를 새로 만들어야 한다. **루트 것은 안 읽힌다** |
| **`sector/` 포함** | `includeFiles` 한 줄 — **코드에 남는다** | 대시보드 토글 — **코드에 안 남는다** |

① **루트 `vercel.json` 의 `builds` 와 Root Directory 는 함께 쓸 수 없다.** `builds` 의
`src: "api/index.py"` 는 Root Directory 기준으로 풀리므로 `backend/api/index.py` 를
찾다 실패하고, **빌드가 6ms 에 산출물 없이 끝난다**(preview `dpl_7f1ngE9…` 실측).
② 같은 로그가 `WARNING! Due to 'builds' existing in your configuration file, the Build
and Development Settings defined in your Project Settings will not apply` 라고 적는다 —
`builds` 가 있으면 **Django 자동 감지(W7)가 아예 기회를 얻지 못한다.**
③ W6 의 "바깥 파일 포함" 토글은 실재하지만, 그것을 켜도 ①②는 그대로다.
④ 🔒 **`.vercelignore` 가 Root Directory 쪽으로 따라간다는 점이 가장 위험했다** —
루트 `.vercelignore` 가 `/data/`(KRX 원천 · 제약 10)와 `.streamlit/`(시크릿)을 막고
있는데, Root Directory 를 옮기면 그 방어가 조용히 사라진다.

#### 원문과 무엇을 잘못 봤나

> ~~"의존성 분리는 **Vercel Root Directory** 로 한다. 파일을 옮기지 않는다.
> Vercel 은 `backend/requirements.txt` 를 읽는다 — **이미 있다.**
> `sector/`·`dashboard/` 를 Django 가 import 해야 하므로 **"Include source files
> outside of the Root Directory" 토글을 켠다.**"~~

틀린 전제는 둘이다. (ㄱ) *"Vercel 에는 루트 `requirements.txt` 가 있어야 한다"* —
`api/` 안을 읽는다는 것을 **문서에서 확인하지 못해 없다고 가정**했다. 로그에는 있었다.
(ㄴ) *"`backend/requirements.txt` 는 이미 Vercel 용이다"* — 그 파일은 **개발용 full
목록**이다. Vercel 용 slim 목록은 `api/requirements.txt` 고, 왜 두 벌인지가 그 파일
머리주석에 이미 적혀 있었다.

🔒 **대안(엔트리포인트를 `app/` 으로 옮기는 안)은 여전히 쓰지 않는다.** 다만 그때 근거로
든 *"설정으로 되는 일을 코드로 만들지 않는다"* 는 여기서 **뒤집힌다** — 이 건에서는
설정(대시보드 토글)이 코드보다 비싸다. 번들이 8배가 되고, `.vercelignore` 방어가
사라지며, `sector/` 포함 여부가 저장소에 남지 않는다. **`api/index.py` 는 이미 쓰여
있고 왜 있는지가 머리주석에 있다** — 기억에 의존하는 코드가 아니다.

⚠️ **`sector/`·`dashboard/` 는 아직 번들에 없다.** 루트 `.vercelignore` 가 셋(+`batch/`)을
빼고 있다 — v2.0 화면이 import 하지 않으므로 지금은 맞다. **렌더러 B(섹터 화면)를 쓰는
날** `.vercelignore` 에서 `sector/`·`dashboard/` 를 풀고 `vercel.json` 의 `includeFiles`
를 `backend/**` 에서 넓힌다. 🔒 `batch/` 는 **풀지 않는다**(수집·집계는 로컬이다).

### ④ 쓰기 상태는 Supabase, 파생값은 HF — **이중 보관**

| 무엇 | 어디 | 왜 |
|---|---|---|
| **팀 원장** (조 · 참가 · 확정 · 코멘트) | **Supabase** | 동시 쓰기 · 실시간 · RLS. 수천 행 · 수MB |
| **파생 집계·점수** (`score_daily` · `sector_daily`) | **HF private dataset** | 3개월이면 수십MB로 자란다. **DB 500MB 에 넣을 물건이 아니다**(W9) |
| **KRX 원천** | 🔒 **로컬에만** | [ADR-SC-0006](0006-krx-데이터-제3자-제공-금지.md) · 약관 제11조② |

🔴 **제약 10 은 Supabase 에도 그대로 붙는다.** "HF 가 아니라 Supabase 니까 괜찮다"
가 아니다 — 제3자 제공 금지는 *어디로 보내는가*가 아니라 *원천인가 파생인가*로
갈린다. **Supabase 에 올라가는 것도 파생값뿐이다.**

**7일 pause 는 배치가 푼다** — 매일 도는 `batch.publish` 가 Supabase 에 한 줄
(게시 로그)을 쓰면 타이머가 리셋된다. 🔒 **GitHub Actions keep-alive 를 쓰지 않는다**
(절대 제약 6 — CI/CD 를 필수 경로에 두지 않는다).

### ⑤ 기존 Supabase 프로젝트를 **재사용**한다

`stock-coin-trade`(`sgbhrahtewojmicwmxxu`)를 그대로 쓴다.

- **전부 0행**이라 v2.0 53개 테이블을 정리해도 잃을 것이 없다(W11)
- 무료 티어는 **활성 2개**가 한도인데 지금 1개를 쓰고 있다. 새로 파면 한도가 찬다(W9)
- 서울 리전(ap-northeast-2) · PG 17.6 — 새로 파도 같은 값이 나온다

### ⑥ 🔒 **RLS 없이 원장을 넣지 않는다**

W12 는 지금 무해하다(0행). 팀 원장이 들어가는 순간 **누가 어느 조의 확정을
지웠는지 알 수 없는 상태**가 된다. 그래서 순서를 고정한다:

> **스키마 설계 → RLS 정책 → 마이그레이션 → 그다음에 데이터.**

⚠️ **정책 없이 `ENABLE ROW LEVEL SECURITY` 만 켜지 않는다** — 전 접근이 막혀 앱이
죽는다. 테이블별 정책과 한 벌로 설계한다. 🔒 **이 저장소는 Public 이므로 anon 키가
공개된다고 가정한다.** passcode 는 지금도 기밀이 아니라 쓰기 권한을 가르는 장치다
(`sector/workspace/auth.py` 머리주석의 위협 모델).

### ⑦ 디자인 토큰을 **한 벌**로 둔다

F-4 팔레트(배경 4단 `#121519 / #191D23 / #21262E / #2A3039` · 의미색 3
`#3DDC97 / #FF6B6B / #8B93A1` · 범주색 5 · radius 8/6/4 · 12/14/16/20/26/34 ·
Pretendard)를 **`.streamlit/config.toml` 에서 먼저 확정**하고, 같은 값을 Django 쪽

🔴 **CSS 만으로 디자인한다는 제약을 버린다.** W2·W3 때문이다 — `config.toml` 이

표현하지 못하는 것만** 남긴다(`.sc-rank` 같은 우리 클래스, `.st-key-*` 국소 조정).

## 근거

**"Streamlit 이라 못생겼다" 는 오진이었다.** W1 이 그것을 뒤집는다 — 팔레트를 아직
안 붙였을 뿐이고, 붙일 자리는 W2 대로 이미 넓다. 오진 위에서 플랫폼을 갈아타면
Django 에서도 같은 일이 반복된다(토큰을 안 정한 Tailwind 는 똑같이 밋밋하다).

**그렇다고 Django 를 안 할 이유는 되지 않는다.** 사용자의 이유는 디자인만이 아니라
**개발 역량과 확장 여지**였고, 그건 오진이 아니다. 서버리스 제약(W8)은 배치를 로컬에
두는 우리 구조에서는 물리지 않는다.

**둘 다 하는 비용이 생각보다 싸다는 것이 이 ADR 의 발견이다.** W6 하나로 의존성
충돌이 풀리고, 코어가 이미 `st` 와 분리돼 있어 두 번째 렌더러가 계산을 다시 쓰지
않는다. 세션 수는 늘지만 **같은 코어를 두 방식으로 보여주는 것**이라 비교 자체가
산출물이 된다.

**이중 보관은 취향이 아니라 용량이 강제한다.** W9 의 500MB 가 선을 긋는다 —
파생 parquet 과 팀 원장은 크기도 접근 패턴도 다르다.
