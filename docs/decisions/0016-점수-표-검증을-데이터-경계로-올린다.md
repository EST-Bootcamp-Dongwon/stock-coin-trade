# ADR-SC-0016 — 점수 표의 검증을 데이터 경계로 올린다

- **상태**: 채택
- **날짜**: 2026-09-19
- **관련**: 이슈 #12 (#7 · #9 적대적 구현 리뷰의 비차단 항목) ·
  [ADR-SC-0007](0007-값을-지어내지-않는다.md) · [ADR-SC-0012](0012-근거-첨부와-확정-모달.md) ④ ·
  [ADR-SC-0014](0014-점수-재현성과-가중치-슬라이더의-경계.md) · 절대 제약 8·12
- **개정하지 않는 것**: 4축 정의 · 프리셋 가중치 · 게시 경로 · 원장 · 점수 재현성 계약 ·
  **의존 증가 0** · **마이그레이션 0**
- **바꾸는 것**: `dashboard/data.py` `load_scores()` 의 **계약**

## 맥락 — 캡션이 읽을 수 없는 프레임으로 숫자를 단언했다

`view.scored()` 가 `ViewError` 를 던져 "이 프레임은 읽을 수 없다" 고 선언한 화면에서,
**그보다 먼저 그려진 캡션이 그 프레임을 근거로 숫자를 단언했다.** 섹터로 거른 부분
프레임으로 랭킹을 띄운 실측(AppTest):

```
caption   기준일 20260909 · 섹터 1개 중 1개 표시 · 균형 … · 정의 `t`
error     점수 표가 화면이 읽을 수 있는 모양이 아니다 — 파생본을 다시 만들어야 한다.
caption   데이터 출처 — 한국거래소 통계정보
```

"섹터 1개 중 1개 표시" 는 **부분 프레임에서 정확히 오해의 원인이 되는 문장**이다 —
이슈 #7 이 닫은 것이 바로 "21개 중 3위" 가 "5개 중 1위" 로 바뀌는 사고다.
읽을 수 없다고 선언한 프레임에서 센 수라 **절대 제약 8** 의 경계에 있다.

병의 뿌리는 캡션의 위치가 아니라 **검증이 `scored()` 안에만 있었던 것**이다. 그래서
페이지마다 보호 수준이 달랐다 — 랭킹만 `ViewError` 를 잡았고, 조 페이지(`pages/teams.py`)와
읽는 법(`pages/howto.py`)은 잡지 않아 팀원이 트레이스백을 볼 수 있었다.

## 결정

### ① `load_scores()` 의 계약을 "**화면이 읽을 수 있는** (프레임, 출처)" 로 바꾼다

캐시 함수를 `_read_scores()` 로 사유화하고 공개 `load_scores()` 를 검사 래퍼로 만든다.

🔒 **규칙으로 막지 않고 경로를 없앤다.** 검사를 지나지 않은 프레임을 얻는 공개 함수가
존재하지 않는다 — AGENTS.md 2장이 `devlee328288` 원격에 쓴 것과 같은 논리다. 다음에
페이지가 하나 늘어도 보호 수준이 갈리지 않는다.

### ② 검사는 **캐시 밖**이다

안에서 던지면 예외가 캐시되지 않아 깨진 파생본에서 rerun 마다 원천을 다시 읽는다(F 의
260.6ms). 밖이면 1.43ms 가 붙는다(A·D).

🔴 **판정을 캐시하는 변형**(캐시 안에서 검사하고 사유 문자열을 함께 돌려주기)을 검토했고
**기각한다.** 히트 경로 비용이 0 이 되지만, 그러면 판정이 **캐시가 돌려준 사본이 아니라
저장 시점의 원본**을 보증하게 된다. 지금 방식은 **호출자가 실제로 받는 그 사본**을 매번
검사한다. 2.3~2.9% 는 그 보증의 값으로 싸다.

### ③ 진단의 **꼬리는 읽는 사람에 따라 다르다**

`check_frame(frame, *, origin="")` — `origin` 을 주면 두 가지가 바뀐다.

| | `scored()` 경로 (개발자) | 데이터 경계 (팀원) |
|---|---|---|
| 꼬리 | `— 거르지 않은 전체 프레임을 넘겨야 한다` | `— 파생본을 다시 만들어야 한다` |
| 읽은 곳 | 붙지 않는다 | `읽은 곳 — {label} ({detail})` |

🔴 팀원은 아무 프레임도 "넘기지" 않았다. 같은 문장을 두 곳에 쓰면 한쪽에서 반드시
거짓말이 된다.

🔴 **읽은 곳이 곧 "무엇을 다시 만들어야 하나" 다.** HF 게시본이면 다시 게시해야 하고
로컬이면 `build_scores` 를 다시 돌려야 한다. 경계에서 던지면 `ranking.render()` 의
`source_label = source.label` 줄에 닿지 못해 푸터의 "이 화면이 읽은 것" 이 사라지므로,
그 사실을 **메시지가 들고 간다.** `data.py` 머리주석이 값과 출처를 함께 돌려주는 이유가
실패 경로에도 그대로 적용된다.

### ④ 세 페이지가 같은 문장을 쓴다 — `theme.BROKEN_SCORES`

페이지마다 문장을 들고 있으면 보호 수준이 갈린 상태가 눈에 띄지 않는다. 조 페이지는
🔒 **조용히 빼지 않는다**(ADR-SC-0007) — 왜 «이 섹터의 근거» 칸이 없는지 말한다.

⚠️ 조 페이지의 피해는 근거 칸에 그치지 않았다 — `_scores()` 는 확정 여부를 보기 **전에**
불리므로, 확정하지 않은 조의 조원도 깨진 파생본에서 참가·보관·기록까지 잃었다.

### ⑤ `scored()` 의 검사를 **지우지 않는다**

경계가 못 보는 것이 있다 — **호출자가 거른 프레임**을 넘기는 경우(이슈 #7 의 실제 버그).
두 검사는 다른 것을 막는다.

## 받아들인 대가

- rerun 당 **+1.9~2.45ms**(+2.3~2.9%). 이슈 #1·#2 가 고친 지점(361→27.5ms · 606→85ms)을
  되돌리지 않는다. 🔒 진짜 낭비는 이 5번째가 아니라 **같은 프레임을 rerun 마다 4번 검사하는
  것**이다(C) — 이번 범위 밖이지만 적어 둔다.
- 🔴 **로컬 경로에는 게시 게이트가 없다.** `_check_whole` 은 게시 계약의 재확인인데
  `data/derived/score_daily.parquet` 는 게이트를 안 지난다. `build_scores` 중간 산출물이
  비조밀하면 이제 **앱 전체**가 꺼진다(전에는 랭킹만). 값을 지어내는 것보다는 낫다.
- `dashboard/data.py` → `dashboard/view.py` 의존이 새로 생긴다. 순환은 없다 —
  `view` 는 `dashboard.weights`·`sector.*` 만 알고, `sector/` 가 `dashboard` 를 모르는 것은
  `agent_test.test_점수_경로는_에이전트를_모른다` 가 지킨다.

## 기각한 대안

| 대안 | 왜 아닌가 |
|---|---|
| **(b) 캡션만 `scored()` 뒤로 내린다** | 옮길 수는 있다(E — 이슈 본문의 "위젯 제약 때문에 못 옮긴다" 는 **틀렸다**). 그러나 **불충분하다**: 깨진 프레임 + `?as_of=…&sector=…` 에서 링크 보고 3줄이 남아 ① 읽을 수 없다고 한 프레임의 기준일로 **방향까지 단언**하고 ② "링크의 `sector` 값을 쓸 수 없어 기본값으로 열었다" 고 **거짓**을 말하며(링크는 멀쩡했고 프레임이 부분 프레임이었다) ③ 그 문장이 가리키는 "화면 위 캡션" 이 없다. 그리고 조·읽는 법 페이지는 그대로 트레이스백이다 |
| **(c) `scored()` 호출을 캡션 위로 한 줄 올린다** | 1줄로 랭킹은 고쳐지고 출처도 산다(실측). 그러나 ① 조·읽는 법 페이지를 고치지 못하고 ② 「경계가 계약을 지킨다」 는 구조적 성질이 없어 다음 페이지에서 되살아나며 ③ `_apply_link` 가 이미 돌아 깨진 로드에서 `_APPLIED` 가 서므로 같은 세션의 다음 성공 로드에서 **공유 링크를 잃는다**(경계 방식은 세우지 않는다) |
| **(d) 오류일 때 캡션을 비운다** | Streamlit 은 이미 그린 것을 지울 수 없다 |
| **(e) 깨진 프레임도 `DataUnavailable` 로 뭉친다** | "아직 안 만들었다"(→ 배치를 돌려라)와 "만들었는데 모양이 틀렸다"(→ 다시 만들어라)는 **다른 행동**을 요구한다. AGENTS.md 의 "못 붙는 것과 잘못 붙는 것은 다르게 다뤄야 한다" 와 같은 모양 |
| **(f) 판정을 캐시한다** | ② 참조 — 사본이 아니라 원본을 보증하게 된다 |
