## 결정

### ① 거절은 규칙이 하고, 네 의도는 문자 n-gram 이 가른다 — 모델은 넣지 않는다 (사용자 결정)

사용자는 처음 "HF 모델을 리서치해서 가져다 쓰자" 고 했고, Z2~Z7 을 보고 규칙 + n-gram 을 골랐다.

```
① normalize(폭 없는 문자 삭제) → ② 거절 규칙 — 가리기 전 문장 → ③ 섹터 이름을 어절 머리에서 찾아 "섹터" 로 가린다
→ ④ 거절 규칙 — 가린 문장 → ⑤ 두 섹터 이상이면 거절 → ⑥ "1위가 어디냐" 는 순위 표를 가리킨다
→ ⑦ 키워드로 후보 의도를 좁힌다 → ⑧ n-gram 최근접(Fraction) → ⑨ 1·2위 차가 작거나 너무 멀면 되묻는다
→ ⑩ "무엇이 바뀌었나" 는 비교 창을 읽고, 못 읽으면 되묻는다
```

- 🔒 **거절이 의도를 이긴다.** "순위 믿고 사도 돼?" 는 믿음을 묻는 척하는 매매 질문이다.
- 🔒 **어절 경계를 지킨다** — "사도" 는 "회사도" 에도 있다. **과거형과 사실 질문은 거절하지 않는다** —
  "올랐어" · "매도세였어" · "진입 장벽".
- 🔒 유사도는 정수 가중치 Dice 를 `Fraction` 으로 — **float 가 없다**(Z7). 판정이 CPU 에 따라 뒤집히지 않는다.
- 🔒 **모델을 들이는 조건** — `agent_test` 의 질문 평가셋(거절 세트 + **잘못 거절하면 안 되는 세트**)에서
  이기고, 의존 · 메모리 · 라이선스 비용을 설명할 수 있을 때. 라우터 경계(`intent.route`)는 그대로 둔다.

| 무엇이 들어 있나 | GICS · ETF · 구성종목 · 유동성 · 묶은 방식 카드 | 산업 정의와 범위 |

🔴 "무엇을 담나" 는 그대로 두면 추천 문장이 된다.

### ③ 위치는 `dashboard/agent/` 다 (사용자 결정)

- import 방향이 **dashboard → sector 한 방향**이다. 엔진은 `view` · `explain` 을 쓰므로 `sector/` 에 두면 방향이 뒤집힌다
- `sector/` 는 점수 계산 경로다 — 절대 제약 3 이 Agent 를 거기서 떼어 두라고 한다
- 🔒 정적 검사 둘 — **에이전트는 읽기만 한다**(streamlit · 네트워크 · 원장 쓰기 · 벽시계 · LLM SDK import 0) ·
  **점수 경로는 에이전트를 모른다**(`sector/` · `batch/` 에 `dashboard` import 0)

### ④ guard 는 세 겹이고, 통과하지 못하면 문장을 버린다

1. **장부 ↔ 원천** — 근거 한 줄마다 `origin`(열 · 파생 · 규칙 · 정의 · 원장)을 달고, guard 가 **`view` 를
   거치지 않고** 점수 표 · `sectors.yaml` · 원장에서 다시 얻어 대조한다. 앞 단계가 넘긴 값을 사실로 삼지 않는다.
2. **문장 ↔ 원천** — 숫자는 `⟦EV-RANK|int⟧` 같은 **자리**로만 문장에 들어간다(Z12). guard 는 원천 값으로
   자리를 **다시 채워 글자까지** 맞춰 보고, 자리 밖의 숫자 · 허락되지 않은 모양(부호를 뗀 σ) · 맞지 않는
   단위(순위 뒤에 "개")를 거부한다. 방향 낱말은 **역할과 상관없이** 찾아 그 낱말을 검사하는 역할에만
   허락하고, 원천 부호와 맞춰 본다(Z15). 쓰지 않는 표현 · 빈 값의 글자가 없어야 한다.
3. **구성 ↔ 원천** — 어느 카드가 나와야 하는지 · 카드 제목 · 칸마다 어느 상수가 와야 하는지(필요한 한계가
   빠졌는지까지) · 반론 일곱의 **판정 갈래와 방어 문장**을 guard 가 원천으로 **따로 다시 정해** 맞춰 본다(Z16).

- 🔒 **고정 문장은 `FIXED_TEXTS` 의 글자 그대로만** 쓴다. 어느 칸에 어느 상수가 오는지는 3 이 정한다.
- 🔒 **문턱은 낱말로 적는다**("세 계단 안에") — 문턱 숫자까지 근거로 만들면 규칙 상수가 장부를 덮는다.
- 🔴 **통과하지 못하면 문장을 그리지 않는다.** 화면은 숫자 칸만 남기고 "원천과 어긋난 것이 나왔다" 고 말한다.
- 🔒 guard 테스트는 **망가뜨린 브리프를 전부 잡는지**까지 본다 — 통과만 보는 guard 테스트는 아무것도 막지
  않는 guard 와 구별되지 않는다. 리뷰가 통과시킨 변조가 하나씩 테스트로 남아 있다.
- 🔒 새 방향 낱말 · 문장 역할 · 근거 자리를 더하면 guard 의 표도 함께 더한다. **자리 모양 표에 없는 근거가
  문장에 나오면 guard 가 거부한다** — 잊으면 드러난다.

### ⑤ GIC 구조를 이렇게 각색했다

| 장치 | 여기서 | 각색한 점 |
|---|---|---|
| 자료 확보의 단계 | 게시 파생값 · 섹터 정의 · 원장 → 없으면 빈칸 | 🔒 **검색하지 않는다.** 검색하지 못한 사실을 밝혀 두는 장치를 따라 화면에 한 줄 남긴다 |
| 신뢰도 상 · 중 · 하 | 상 = 창이 온전한 거래소 파생값 · 규칙 · 원장 기록 / 중 = 척도를 내린 축 · 표본일 부족 · 결측 축이 섞인 총점 · 원천과 대조한 식별자 / 하 = 사람이 쓴 판단 | 원문의 중(2차 매체)이 우리에게 없어 **계산 품질**로 옮겼다(사용자 결정) |
| Gap Log | 여섯 칸 필수 · 결측 유형 셋 · 상태 신규 / 유지 / 닫힘 | 🔒 **구조적 비공시에는 체계가 없다는 증거가 필수**(dataclass 불변식). 닫힘은 **같은 섹터 · 같은 질문 · 같은 기준일 · 같은 창**일 때만 — 다른 질문에서 안 나온 빈칸은 채워진 것이 아니다 |
| 고정 ID 대장 | `TH-` 논점 · `RK-` 리스크 · `AT-` 공격 · `GP-` Gap · `EV-` 근거 | ID 가 카탈로그의 열쇠라 번호를 새로 매길 일이 없다. 은퇴한 ID 는 `RETIRED` 로. 이 도구에 없는 단계의 접두사(`IP-` · `CT-` · `CD-`)는 쓰지 않는다 |
| 방어의 세기 상한 | 숫자 근거 없는 [통과] 불가 · 근거 없으면 [추가확인] + 빈칸 | 원문은 챗봇에게 **부탁**했다. 여기서는 **불변식**이고, guard 가 판정을 원천으로 다시 매긴다 |
| 해석 카드 여섯 칸 | 관찰 사실 / 의미 / 가능한 원인 가설 / 반대 해석 / 한계 / 다음 확인 지표 | 🔴 **원인 가설 칸은 "말할 수 없다"** — 원인의 재료(뉴스 본문)는 약관상 가공할 수 없다(V6). 빈칸도 지어내기도 아니고 Gap 이다 |
| AI 해석안 · 사람 승인 | 엔진은 판정하지 않는다 | 사람의 승인은 **조의 확정**(ADR-SC-0012)이다. Proceed / Watch / Drop 같은 판정 낱말을 guard 가 거부한다 |
| 인계 블록 | `Handoff` — 섹터 · 기준일 · 정의 버전 · 창 · 확정값 · ID 대장 · 구조적 목록 · 미해결 Gap · 다음 질문 | **후속 질문의 맥락**으로 쓴다. 🔒 화면에서 고른 섹터가 바뀌면 버리고, 사람이 물은 답에서만 만든다 |
| 사용자 의견 질문 | "다음에 물어볼 것" — 나머지 의도 셋 | 의견 반영 기록은 두지 않았다 — 원장이 그 역할을 한다 |
| 기준일 셋 | 데이터 기준일(`bas_dd`) · 정의 버전(`config_version`) | 통계 · 가격 기준일이 같은 원천에서 오므로 둘로 줄였다 |

### ⑥ 질문이 다른 섹터를 적으면 그 섹터로 답하고 머리에 적는다 (사용자 결정)

섹터를 정하는 순서 — 질문에 적힌 섹터 → (화면의 섹터가 그대로면) 앞 질문에서 이어진 섹터 → 화면에서 고른 섹터.
화면의 섹터와 다르면 **어디서 온 섹터인지**("질문에 적힌" · "앞 질문에서 이어진") 머리에 적는다. 두 섹터 이상이면
거절한다(견주는 일은 랭킹 표가 같은 잣대로 한다). GICS 대분류 이름이면 그 안의 섹터를 알려 주고 되묻는다.

### ⑦ "압도적으로" 를 쓰지 않는다 (사용자 결정)

`explain.sigma_words` 의 가장 높은 구간을 **"2σ 이상 높다"** 로 바꿨다. 무엇 대비 얼마나인지 말하지 않는
낱말이다. 에이전트는 같은 구간을 자리로 적고(`compose.sigma_band`), 두 함수가 같은 말을 하는지 테스트가 대조한다.

### ⑧ 비교 창 — 못 읽으면 되묻고, 확정 이후는 확정한 날(KST) **전의** 마지막 기준일

- 숫자는 **영업일 · 거래일 · 주(5영업일) · 달(20영업일)** 로만 받고, 답은 실제 비교 기준일을 날짜로 적는다.
  "N일"(달력일인지 모른다) · 날짜 · 해 단위 · 60영업일 초과는 **되묻는다**(Z13). 창을 적지 않으면 기본 5영업일을
  쓰고 **그렇다고 적는다**
- "확정한 뒤로" — 그날 데이터는 다음 날 아침에 게시되므로 확정 당시 화면에 있던 날에 가장 가깝다.
  🔒 **정확히 같다고 말하지 않는다** — 화면이 이 정의를 그대로 적는다. 조 원장을 읽는 **조 페이지에서만** 답하고,
  랭킹에서 물으면 Gap 이다

### ⑨ 화면 — 질문칸은 랭킹과 조 페이지에만

- 질문하지 않으면 "왜 이 자리인가" 가 기본으로 보인다. 질문 버튼 넷이 예시 문장을 채운다
- 🔒 **확정 모달에는 질문칸을 두지 않는다** — 사유를 쓰는 자리다
- 🔒 **섹터를 바꾸면 질문칸과 인계를 비운다**(Z18)
- 🔒 **질문 글자를 어디에도 되돌려 그리지 않는다.** 화면의 문장은 전부 코드와 `sectors.yaml` 이 쓴 것이다 —
  사람 글이 마크다운에 들어가는 경로를 새로 열지 않는다(ADR-SC-0012 ④)
