## 맥락

이 저장소는 강사님 원본 `edumgt/stock-coin-trade` 를 clone 한 **진짜 fork** 다.
`upstream` 원격과 `upstream-main` 브랜치가 살아 있고, 강사님 최신을 받을 때
평범한 3-way merge 로 얹힌다.

같은 모노레포의 `investment-analysis` 는 원본을 파일 복사로 시작해 계보가 끊겨 있다.
그쪽은 이제 원본을 받을 방법이 없다. **여기는 아직 그 능력이 있다.**

한편 이 저장소는 v2.0(Django) 재작성이 진행 중이라 "낡은 v1.0 파일들을 `legacy/`
아래로 정리하고 싶다" 는 유혹이 계속 생긴다. `python-stock-backend/`·`frontend/`·
`database/`·`docker/` 가 그 대상이다.

## 결정

**파일을 대거 이동·개명하지 않는다. 제자리에서 고친다.**

- v1.0 코드는 지금 위치에 그대로 둔다. `legacy/` 같은 폴더를 만들지 않는다.
- 개명이 꼭 필요하면 `git mv` 로 **1건씩**, 이유를 커밋 메시지에 남긴다.
- 저장소 전체에 포맷터(`ruff --fix` 등)를 돌리지 않는다. 새로 쓴 파일에만 적용한다.
- `upstream-main` 에 직접 커밋하지 않는다 — 강사님 원본 미러다.

## 근거

Git 은 이름을 저장하지 않고 **내용 유사도로 rename 을 추론한다.** 파일을 옮기면서
내용까지 손대면 추론이 깨지고, 다음 merge 에서 "삭제 vs 수정" 충돌이 파일 수만큼 난다.
대규모 포맷팅은 **모든 줄을 바꾼 것과 같아서** 같은 결과를 만든다.

이동으로 얻는 것은 보기 좋음이고, 잃는 것은 **강사님 코드를 받을 능력**이다.
비대칭이 크다.

## 결과

- ✅ 강사님 최신을 `sync/upstream-<날짜>` 브랜치에서 평범하게 merge 할 수 있다.
- ✅ `git diff upstream-main main --stat` 이 "내가 바꾼 것" 을 정확히 보여준다.
- ⚠️ 저장소 루트에 v1.0 과 v2.0 파일이 섞여 있어 처음 보면 헷갈린다.
  → `AGENTS.md` 1장과 `README.md` 머리말이 그 지도를 준다. **문서로 푼다, 이동으로 풀지 않는다.**
- ⚠️ "정리" 를 요청받아도 이 ADR 을 근거로 되묻는다.
