# ADR-SC-0006 — KRX 데이터를 제3자에게 제공하지 않는다 (HF 에는 파생값만)

- **상태**: 채택
- **날짜**: 2026-09-11
- **관련**: [ADR-SC-0005](0005-산출물-재지정과-이력-재시작.md) · [ADR-SC-0007](0007-값을-지어내지-않는다.md)

## 맥락

섹터 스코어링은 국내 시세·ETF 데이터를 매일 쌓아야 한다. 저장소에 담을 수는 없으니
Hugging Face Hub(Pro · 비공개 1TB)에 두려 했다.

그런데 2026-09-11 약관 조사에서 **경로 대부분이 막혀 있다**는 것이 드러났다.

| 조항·사실 | 내용 |
| --- | --- |
| KRX Open API 약관 **제11조②** | **"API 이용자는 한국거래소로부터 제공받은 정보를 제3자에게 제공할 수 없다."** |
| 같은 조 **④** | 위반 시 **이용승인 철회 및 서비스 중단** |
| **제6조②** | **비상업적 목적으로만** 이용 가능 |
| **제10조③** | 결과로 화면을 만들면 **"한국거래소 통계정보"를 사용했음을 명시**해야 한다 |
| KRX FAQ | **`pykrx` 를 이름으로 지목**해 "과도한 접속 시 IP 차단, 해제도 원칙적으로 어렵다" |
| 홈페이지 약관 제10조② | **자동화 수단을 이용한 무단 수집·복제·배포 금지** |
| KRX FAQ | 다만 **광고·유료 기능이 없고 출처를 표시한 "가공 결과의 화면 표출"은 가능** |

**비공개 저장소라도 팀원 7명은 제3자다.** 조항은 공개 여부가 아니라 *제공* 을 금지한다.

## 결정

**① 원천 데이터를 저장소·HF 어디에도 올리지 않는다. 로컬에만 둔다.**

| | 어디에 | 왜 |
| --- | --- | --- |
| `etf_daily` · `stock_daily` **원천** | 🔒 로컬 `data/raw/` (gitignore) | 제11조② |
| `sector_daily` (섹터 단위 집계) | HF 비공개 | 파생값 |
| `score_daily` · `sector_master` | HF 비공개 | 자체 산출물 |

**② 집계값도 원천 복원이 가능하면 지수화한다.** 섹터에 ETF 가 하나뿐이면 순자산 가중
종가가 그 ETF 종가와 같아진다. 그런 경우 **기준일=100 으로 지수화해서** 올린다.
절대가격을 올리지 않는다.

**③ 앱에 원자료 다운로드 버튼을 두지 않는다.**

**④ 모든 화면에 "한국거래소 통계정보" 출처를 표시한다.** (제10조③ 의무)

**⑤ `pykrx` 를 쓰지 않는다.** 주 경로는 인증키 기반 **KRX Open API**
(`data-dbg.krx.co.kr/svc/apis/`)다. 인증키 발급과 **개별 API 이용승인**을 따로 받는다.

**⑥ 업로드 직전에 서버에 다시 물어 private 이 아니면 한 파일도 올리지 않고 멈춘다.**

```python
def assert_private(api, repo_id: str) -> None:
    # create_repo(exist_ok=True) 는 대상이 public 이어도 그냥 성공한다.
    # 그래서 "만들 때 private 으로 만들었다" 를 믿지 않고 올리기 직전에 다시 묻는다.
    if not api.repo_info(repo_id=repo_id, repo_type="dataset").private:
        raise PublishBlocked(f"{repo_id} 가 public 입니다. 한 파일도 올리지 않습니다.")
```

## 근거

기술적으로 되는 것과 **허용된 것은 다르다.** `pykrx` 가 동작한다고 해서 KRX 가 그 취득 방식을
허용한다는 뜻이 아니고, 거래소가 라이브러리 이름을 콕 집어 경고한 이상 운영 경로에 둘 수 없다.

공개 저장소에 코드가 드러나는 상황에서 약관 위반 경로를 쓰면 **계정·서비스 차단 위험**이 있고
포트폴리오로서도 흠이 된다. 반대로 "집계·파생값만, 출처 표시, 비상업"은 FAQ 가 명시적으로
허용한 범위 안이다. **경계 안에 머무는 설계가 곧 안전한 설계다.**

부수 효과도 있다 — 원천을 올리지 않으니 HF 저장소가 작아지고, Streamlit 앱이 받아야 할
데이터도 줄어 메모리 한도에 여유가 생긴다.

## 결과

- ✅ 제11조②·제6조②·제10조③ 을 모두 지킨다.
- ✅ HF 저장소가 수 MB 수준으로 작아진다. 앱은 `latest/` 파일만 읽는다.
- ⚠️ 개별 종목 일봉을 HF 에 둘 수 없어 **앱이 조회 시점에 받아야 한다.**
  사용자가 한 번에 보는 종목은 1~3개라 실용상 문제가 없다.
- ⚠️ KRX Open API 는 **개별 API 이용승인**이 따로 필요하다. 승인이 늦으면 착수가 막히므로
  **가장 먼저 신청한다.**
- ⚠️ 인증키는 유효 1년 · 자동연장 없음 · 12개월 미사용 시 삭제. 만료 전 연장한다.
